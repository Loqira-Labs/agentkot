# Files

通过私有虚拟层读取和修改文件。该工具可处理文本、二进制数据、图像、笔记本、代码和目录；更改先进入虚拟层，只有通过同步操作才会转移到磁盘。

## 操作

操作由 `operation` 字段选择。若省略该字段，则根据参数集合推断操作：存在 `content`、`content_base64`、`autocreate` 中的任意一个即视为 `write`；否则存在 `old_string`、`new_string`、`replace_all`、`cell_id`、`cell_type`、`cell_edit_mode` 中的任意一个即视为 `edit`；否则为 `read`。未知的 `operation` 值会返回错误。

### read

读取文件或目录。结果格式取决于路径类型：文本文件、图像、笔记本、代码，或目录条目列表。缺失的文件以软结果返回（不是错误），因此无需预先检查是否存在。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 是 | — | 文件或目录的路径；相对路径相对于会话工作目录解析 |
| offset | integer or string | 否 | 1 | 开始读取的行号（从 1 计数）；0 表示 1 |
| limit | integer or string | 否 | — | 要读取的最大行数；设置后会禁用字节读取限制 |
| virtual | boolean or string | 否 | true | 从虚拟层读取未同步的版本；false 表示读取磁盘上的真实文件 |
| revirtual | boolean or string | 否 | false | 仅与 `virtual: false` 配合使用；丢弃该路径下未同步的虚拟层条目 |
| depth | integer or string | 否 | 1 | 读取目录时的递归深度；最大 64 |
| view | string | 否 | skeleton（代码） | `full`、`skeleton` 或 `symbols`（针对代码文件） |
| symbol | string | 否 | — | 要完整读取的代码文件符号的名称 |

文本文件以行号返回：每行前面有一个右对齐的数字（宽度至少 6 个字符）和一个制表符。结果包含路径、内容、该片段的行数、片段首行的行号，以及文件的总行数。空文件返回文件为空的提示；超出文件末尾的 offset 返回超出范围的提示。

不带行范围读取代码文件时，默认返回结构（skeleton）：签名及折叠为 `{ … }` 的函数体，带行号。`view: "symbols"` 返回扁平的符号列表，`view: "full"` 返回原文内容，`symbol` 返回单个符号的原文内容。指定 `offset`/`limit` 时按原文读取文件。支持的扩展名：rust、python、javascript、typescript、tsx、go、java、c、c++。

以 `depth` 1（默认）读取目录返回一层：先是子目录，后是文件，各自按名称排序。`depth > 1` 时返回跨整个子树的扁平列表，按相对路径排序。结果限制为 1000 个条目（超出时设置截断标记）。每个条目包含名称、目录标志、以字节为单位的大小（目录无此项）、存在情况（在磁盘上、仅在虚拟层、两者都有）、未同步更改标志、是否有子项标志，以及（对于递归列表）相对于目录的路径。

读取图像返回 base64 编码的内容和 MIME 类型。图像边长限制为 2000 像素：超出则按比例缩小；宽高比达到 3 或以上的图像沿短边切成正方形切片。MIME 类型由数据头确定，而不是由扩展名确定。空图像文件（0 字节）会被拒绝。

读取 `.ipynb` 笔记本时，以 `<cell id="…" type="code|markdown">` 标签返回单元格。笔记本完整读取，限制为 256 KB。

读取标记为删除的路径会返回软结果 "deletion pending"；以 `virtual: false` 读取则显示磁盘上的副本。

### write

创建新文件或覆盖现有文件。内容进入虚拟层，而不是磁盘。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 是 | — | 要写入的路径 |
| content | string | 二选一 | — | 完整文本内容 |
| content_base64 | string | 二选一 | — | base64 编码的二进制内容 |
| autocreate | boolean or string | 否 | true | 创建缺失的父目录 |

`content` 与 `content_base64` 互斥；二者必须恰好提供其一。二进制数据按字节原样写入，不做转换。创建新文件无需预先读取；覆盖现有文本文件需要预先完整读取（部分或结构化读取会被拒绝）。写入文本时将行尾规范化为 LF；新文件使用不带 BOM 的 UTF-8 编码和 LF 行尾。

### edit

替换现有文件中的精确字符串。对于 `.ipynb`，执行单元格编辑。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 是 | — | 要修改的路径 |
| old_string | string | 是（.ipynb 除外） | — | 要查找并替换的精确字符串 |
| new_string | string | 是 | — | 替换字符串；必须与 old_string 不同 |
| replace_all | boolean or string | 否 | false | 替换所有出现 |
| cell_id | string | 否（.ipynb 的 replace/delete 必填） | — | 单元格标识符或简写形式 `cell-N` |
| cell_type | string | 否（insert 必填） | — | `code` 或 `markdown` |
| cell_edit_mode | string | 否 | replace | `replace`、`insert` 或 `delete` |

字符串匹配时不区分排版引号（弯引号与直引号视为相同）。未找到任何出现时返回错误；存在多个出现且未使用 `replace_all` 时，返回错误并指出出现的次数。`old_string == new_string` 会被拒绝。空的 `old_string` 在文件不存在时创建新文件，或向已有的空文件插入内容；对于非空的已有文件则返回错误。编辑会保留文件检测到的行尾。

在笔记本中，`insert` 需要 `cell_type`；`replace` 和 `delete` 需要 `cell_id`（标识符或 `cell-N`）。不带 `cell_id` 的 `insert` 会在位置 0 插入新单元格，否则插入到指定单元格之后。以 `cell-N` 进行 `replace` 时，若 N 等于单元格数量，则在末尾追加一个单元格。新单元格获得 13 个字符的标识符；代码单元格获得 `execution_count: null` 和空的 `outputs` 列表。笔记本以 1 空格缩进序列化。笔记本错误（无效 JSON、找不到单元格）以带错误标志的结果返回。

### delete

在虚拟层中将文件标记为删除。文件在同步之前不会从磁盘移除。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 是 | — | 要删除的文件的路径 |

删除目录会被拒绝。结果报告发生的情况：已标记为删除（文件将在同步时移除）、新文件条目已重置（文件原本不存在于磁盘上）、或文件在任何地方都不存在（软结果）。

### sync

将虚拟层的更改转移到磁盘。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 否 | — | 要同步的路径；省略时同步所有已修改的路径 |

同步遵循「先同步者获胜」原则：如果磁盘上的文件在代理读取之后发生了变化，同步不会覆盖他人的更改。磁盘上不重叠的更改会自动合并；重叠的更改会作为冲突返回，虚拟层会收到带冲突标记 `<<<<<<< staged / ======= / >>>>>>> disk` 的文件，必须读取、解决后再次同步。二进制文件不合并：出现分歧时返回冲突，指示覆盖该文件。结果包含已同步路径的列表（含 create/update/delete 类型、已创建的目录和自动合并标志）以及冲突列表。使用 `autocreate: false` 时，缺失的父目录会作为冲突返回。

### diff

显示虚拟层与磁盘之间的差异。只读。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 否 | — | 要比较的路径；省略时显示所有已修改的路径 |

差异以可显示的统一 diff 片段返回；它不用于作为补丁应用。标记为删除的文件显示为其基础内容的删除；二进制文件显示空片段。

### discard

移除虚拟层条目，将状态恢复到磁盘。磁盘不被修改。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 否 | — | 要重置的路径；省略时重置整个虚拟层 |

### status

显示虚拟层的状态。只读。

| 参数 | 类型 | 必填 | 默认值 | 含义 |
|---|---|---|---|---|
| file_path | string | 否 | — | 要检查的路径；省略时显示所有路径 |

对于每个路径，返回未同步更改标志、磁盘分歧标志和删除标记标志。状态同时显示已修改的条目和干净的读取缓存条目。

## 行为与限制

虚拟层属于单个代理（会话）。写入和编辑在同步之前进入虚拟层；其他代理和外部进程看不到它。读取时默认看到叠加在磁盘之上的虚拟版本。

外部进程（shell、git、编辑器）直接操作磁盘，只能看到已同步的内容。在外部进程需要看到更改之前，要先执行同步。外部写入后，代理的读取缓存可能过时：以 `virtual: false, revirtual: true` 读取会丢弃过时的虚拟层条目。`revirtual` 参数的危险之处在于它会丢弃该路径上未同步的工作——它只应应用于没有自身未同步编辑的路径。

在检查与编辑之间磁盘上的文件发生变化，会以 "file unexpectedly changed" 错误返回，而不是静默写入。对于编辑，触碰文件（只改变时间而不改变内容）是允许的；对于通过 write 进行的覆盖则不允许。

同步时的分歧检查依赖内容哈希，而不是修改时间。同步单个路径在进程内串行化；落在快照与写入之间的编辑不会丢失。

虚拟层保存在内存中，重启后消失。会话启动时，从日志恢复虚拟层：重新应用最后一个重置点之后成功的 write、edit 和 delete 操作。最终内容已与磁盘一致的路径不恢复。重启后无法应用的操作被声明为已跳过，该路径会在下次同步时被标记为强制冲突。同一路径在给定磁盘上大小写不同但重合的两个条目不会合并：较晚的一个被丢弃并报告，该路径在解决之前拒绝同步。

代理内存中的文件发生外部更改时，会在 250 ms 防抖后以文件更改通知的形式送达代理。代理自身的同步不会产生此类通知。

读取限制：完整文本读取和笔记本读取限制为 256 KB（显式指定 `limit` 会为文本禁用该限制）；结构化代码读取限制为 4 MB；最终读取结果限制为 262144 个字符，在行边界处截断。编辑大于 1 GiB 的文件会被拒绝。读取二进制文件按扩展名列表拒绝，对未列出的格式执行 NUL 字节检查。读取 PDF 会被拒绝。设备路径和 UNC 路径在不访问文件系统的情况下处理。

## 示例

读取文本文件，第 10 至 29 行：

```json
{"operation": "read", "file_path": "src/main.rs", "offset": 10, "limit": 20}
```

递归读取目录：

```json
{"operation": "read", "file_path": "rust-agent", "depth": 3}
```

创建新文件：

```json
{"operation": "write", "file_path": "notes/todo.md", "content": "# Tasks\n"}
```

对现有文件做定点编辑：

```json
{"operation": "edit", "file_path": "README.md", "old_string": "version 1.0", "new_string": "version 1.1"}
```

将所有已修改的文件同步到磁盘：

```json
{"operation": "sync"}
```
