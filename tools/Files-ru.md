# Files

Чтение и изменение файлов через частный виртуальный слой. Инструмент работает с текстом, бинарными данными, изображениями, блокнотами, кодом и каталогами; изменения сначала попадают в виртуальный слой и переносятся на диск только операцией синхронизации.

## Операции

Операция выбирается полем `operation`. Если поле опущено, операция выводится из набора параметров: наличие любого из `content`, `content_base64`, `autocreate` означает `write`; иначе наличие любого из `old_string`, `new_string`, `replace_all`, `cell_id`, `cell_type`, `cell_edit_mode` означает `edit`; иначе `read`. Неизвестное значение `operation` возвращает ошибку.

### read

Читает файл или каталог. Формат результата зависит от типа пути: текстовый файл, изображение, блокнот, код или список элементов каталога. Отсутствующий файл возвращается как мягкий результат (не ошибка), поэтому проверять существование заранее не нужно.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | да | — | путь к файлу или каталогу; относительный путь резолвится против рабочего каталога сессии |
| offset | целое число или строка | нет | 1 | номер строки, с которой читать (1-индексация); 0 означает 1 |
| limit | целое число или строка | нет | — | максимальное число читаемых строк; при задании отключает байтовый лимит чтения |
| virtual | булев или строка | нет | true | читать несинхронизированную версию из виртуального слоя; false читает реальный файл на диске |
| revirtual | булев или строка | нет | false | только при `virtual: false`; сбрасывает несинхронизированную запись виртуального слоя для этого пути |
| depth | целое число или строка | нет | 1 | глубина рекурсии при чтении каталога; максимум 64 |
| view | строка | нет | skeleton для кода | full, skeleton или symbols (для кодовых файлов) |
| symbol | строка | нет | — | имя символа кодового файла, читаемого целиком |

Текстовый файл возвращается с нумерацией строк: каждая строка предваряется выровненным вправо номером (ширина не менее 6 символов) и символом табуляции. Результат содержит путь, содержимое, число строк в срезе, номер первой строки среза и общее число строк файла. Пустой файл возвращает сообщение о том, что файл пуст; offset за пределами файла возвращает сообщение о выходе за диапазон.

Чтение кодового файла без диапазона строк возвращает по умолчанию структуру (skeleton): сигнатуры с телами, свёрнутыми в `{ … }`, с нумерацией строк. `view: "symbols"` возвращает плоский список символов, `view: "full"` — дословное содержимое, `symbol` — дословное содержимое одного символа. При указании `offset`/`limit` файл читается дословно. Распознаются расширения: rust, python, javascript, typescript, tsx, go, java, c, c++.

Чтение каталога при `depth` 1 (по умолчанию) возвращает один уровень: сначала подкаталоги, затем файлы, каждый отсортирован по имени. При `depth > 1` возвращается плоский список по всему поддереву, отсортированный по относительному пути. Результат ограничен 1000 элементов (при превышении выставляется признак усечения). Каждый элемент несёт имя, признак каталога, размер в байтах (для каталога отсутствует), присутствие (на диске, только в виртуальном слое, в обоих), признак несинхронизированного изменения, признак наличия дочерних элементов и (для рекурсивного списка) путь относительно каталога.

Чтение изображения возвращает содержимое в формате base64 и MIME-тип. Сторона изображения ограничена 2000 пикселей: превышение ужимается с сохранением пропорций; изображение с соотношением сторон 3 и более нарезается на квадратные плитки по короткой стороне. MIME-тип определяется по заголовку данных, а не по расширению. Пустой файл изображения (0 байт) отклоняется.

Чтение блокнота `.ipynb` возвращает ячейки в виде тегов `<cell id="…" type="code|markdown">`. Блокнот читается целиком и ограничен 256 КБ.

Чтение пути, помеченного на удаление, возвращает мягкий результат «готовится удаление»; чтение с `virtual: false` при этом показывает копию на диске.

### write

Создаёт новый файл или перезаписывает существующий. Содержимое попадает в виртуальный слой, а не на диск.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | да | — | путь для записи |
| content | строка | одно из двух | — | полное текстовое содержимое |
| content_base64 | строка | одно из двух | — | base64-кодированное бинарное содержимое |
| autocreate | булев или строка | нет | true | создавать отсутствующие родительские каталоги |

`content` и `content_base64` взаимно исключают друг друга; ровно одно из них обязательно. Бинарные данные записываются байт-в-байт без преобразования. Создание нового файла не требует предварительного чтения; перезапись существующего текстового файла требует предварительного полного чтения (частичное или структурное чтение отклоняется). Запись текста приводит переводы строк к LF; новые файлы получают кодировку UTF-8 без BOM и переводы LF.

### edit

Заменяет точную строку в существующем файле. Для `.ipynb` выполняется правка ячеек.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | да | — | путь для изменения |
| old_string | строка | да (кроме .ipynb) | — | точная строка для поиска и замены |
| new_string | строка | да | — | строка замены; должна отличаться от old_string |
| replace_all | булев или строка | нет | false | заменить все вхождения |
| cell_id | строка | нет (да для replace/delete в .ipynb) | — | идентификатор ячейки или краткая форма `cell-N` |
| cell_type | строка | нет (да для insert) | — | `code` или `markdown` |
| cell_edit_mode | строка | нет | replace | `replace`, `insert` или `delete` |

Совпадение строки проверяется без учёта типографских кавычек (фигурная кавычка совпадает с прямой). При отсутствии вхождения возвращается ошибка; при нескольких вхождениях без `replace_all` возвращается ошибка с указанием числа вхождений. `old_string == new_string` отклоняется. Пустой `old_string` создаёт новый файл, если файла нет, или вставляет содержимое в существующий пустой файл; для непустого существующего файла возвращается ошибка. Правка сохраняет обнаруженные переводы строк файла.

В блокноте `insert` требует `cell_type`; `replace` и `delete` требуют `cell_id` (идентификатор или `cell-N`). Для `insert` без `cell_id` новая ячейка вставляется в позицию 0, иначе после указанной ячейки. `replace` с `cell-N`, где N равно числу ячеек, добавляет ячейку в конец. Новая ячейка получает идентификатор из 13 символов; кодовая ячейка получает `execution_count: null` и пустой список `outputs`. Блокнот сериализуется с отступом в 1 пробел. Ошибки блокнота (невалидный JSON, ненайденная ячейка) возвращаются как результат с признаком ошибки.

### delete

Помечает файл на удаление в виртуальном слое. Файл не удаляется с диска до синхронизации.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | да | — | путь к удаляемому файлу |

Удаление каталога отклоняется. Результат сообщает, что произошло: помечено на удаление (файл будет удалён при синхронизации), сброшена запись нового файла (файла на диске не было), или файл отсутствует везде (мягкий результат).

### sync

Переносит изменения виртуального слоя на диск.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | нет | — | путь для синхронизации; отсутствие синхронизирует все изменённые пути |

Синхронизация применяет принцип «первый синхронизировавший выигрывает»: если файл на диске изменился с момента, когда агент его прочитал, синхронизация не затирает чужое изменение. Непересекающиеся изменения на диске объединяются автоматически; пересекающиеся изменения возвращаются как конфликт, и виртуальный слой получает файл с маркерами конфликта `<<<<<<< staged / ======= / >>>>>>> disk`, которые нужно прочитать, разрешить и синхронизировать повторно. Бинарный файл не объединяется: при расхождении возвращается конфликт с указанием перезаписать файл. Результат содержит список синхронизированных путей (с видом create/update/delete, созданными каталогами и признаком автоматического объединения) и список конфликтов. При `autocreate: false` отсутствующий родительский каталог возвращается как конфликт.

### diff

Показывает разницу между виртуальным слоем и диском. Только для чтения.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | нет | — | путь для сравнения; отсутствие показывает все изменённые пути |

Разница возвращается в виде отображаемых кусков unified-диффа; она не предназначена для применения как патч. Помеченный на удаление файл показывается как удаление его базового содержимого; бинарный файл показывает пустой кусок.

### discard

Удаляет записи виртуального слоя, возвращая состояние к диску. Диск не изменяется.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | нет | — | путь для сброса; отсутствие сбрасывает весь виртуальный слой |

### status

Показывает состояние виртуального слоя. Только для чтения.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | нет | — | путь для проверки; отсутствие показывает все пути |

Для каждого пути возвращается признак несинхронизированного изменения, признак расхождения с диском и признак помеченного удаления. Статус показывает и изменённые записи, и чистые записи кэша чтения.

## Поведение и ограничения

Виртуальный слой принадлежит одному агенту (сессии). Записи и правки попадают в него до синхронизации; другие агенты и внешние процессы его не видят. Чтение по умолчанию видит виртуальную версию поверх диска.

Внешние процессы (оболочка, git, редакторы) работают напрямую с диском и видят только синхронизированное содержимое. Перед тем как внешний процесс должен увидеть изменения, выполняется синхронизация. После внешней записи кэш чтения агента может устареть: чтение с `virtual: false, revirtual: true` сбрасывает устаревшую запись виртуального слоя. Параметр `revirtual` опасен тем, что отбрасывает несинхронизированную работу для этого пути — его применяют только к пути без собственных несинхронизированных правок.

Изменение файла на диске между проверкой и выполнением правки возвращается как ошибка «файл неожиданно изменён», а не как тихая запись. Для правки допускается касание файла (изменение времени без изменения содержимого); для перезаписи записью — нет.

Проверка расхождения при синхронизации опирается на хэш содержимого, а не на время изменения. Синхронизация одного пути сериализуется в пределах процесса; повторная правка, попавшая между снимком и записью, не теряется.

Виртуальный слой хранится в памяти и исчезает при перезапуске. При старте сессии слой восстанавливается из протокола: повторно применяются успешные операции записи, правки и удаления после последней точки сброса. Пути, чьё итоговое содержимое уже совпадает с диском, не восстанавливаются. Операция, неприменимая после перезапуска, объявляется пропущенной, а путь помечается на принудительный конфликт при следующей синхронизации. Две записи пути с разным регистром, совпадающие на данном диске, не объединяются: более поздняя отбрасывается и объявляется, а путь отказывается синхронизироваться до разрешения.

Внешнее изменение файла, находящегося в памяти агента, доставляется агенту как уведомление об изменённом файле после снятия дребезга в 250 мс. Собственная синхронизация агента не порождает такого уведомления.

Лимиты чтения: полное текстовое чтение и чтение блокнота ограничены 256 КБ (явный `limit` отключает лимит для текста); структурное чтение кода ограничено 4 МБ; итоговый результат чтения ограничен 262144 символами с обрезкой по границе строки. Правка файла крупнее 1 ГиБ отклоняется. Чтение бинарных файлов по списку расширений отклоняется, а для неучтённых форматов выполняется проверка по NUL-байту. Чтение PDF отклоняется. Пути-устройства и UNC-пути обрабатываются без доступа к файловой системе.

## Примеры

Чтение текстового файла строками с 10 по 29:

```json
{"operation": "read", "file_path": "src/main.rs", "offset": 10, "limit": 20}
```

Рекурсивное чтение каталога:

```json
{"operation": "read", "file_path": "rust-agent", "depth": 3}
```

Создание нового файла:

```json
{"operation": "write", "file_path": "notes/todo.md", "content": "# Задачи\n"}
```

Точечная правка существующего файла:

```json
{"operation": "edit", "file_path": "README.md", "old_string": "version 1.0", "new_string": "version 1.1"}
```

Синхронизация всех изменённых файлов с диском:

```json
{"operation": "sync"}
```
