# Memory

Инструмент хранения постоянных заметок агента, отличных от файлов проекта и от истории переписки: заметки живут на диске между сессиями, имеют область видимости и классификацию, индексируются для поиска и автоматически подгружаются в начало каждой сессии. Один инструмент с пятью операциями, различаемыми полем `operation`: `read`, `write`, `list`, `delete`, `search`. Каждая операция принимает поле `scope`.

Области видимости:

| scope | расположение на диске | смысл |
|---|---|---|
| project | `<корень_проекта>/.kot/agent-memory` | заметки проекта; общие через систему контроля версий; используется по умолчанию |
| user | `<config_home>/memory` | заметки на всю машину, общие для всех проектов и сессий |
| local | `KOT_REMOTE_MEMORY_DIR`, либо `<корень_проекта>/.kot/agent-memory-local` | заметки этого проекта на этой машине; чтобы они не попадали в систему контроля версий, каталог добавляется в правила игнорирования репозитория |

## Операции

### read

Читает одну заметку по её имени-слагу в заданной области.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| name | строка | да | — | имя-слаг заметки (стем файла, без расширения `.md`) |
| scope | строка | нет | `project` | область видимости |

Возвращает полную запись: `name`, `title`, необязательный `description`, `kind`, `body` (сырое тело markdown), `scope` и `path` (путь на диске). Отсутствующая заметка — мягкий результат «не найдено», не ошибка.

### write

Создаёт или перезаписывает заметку и её строку в индексе. Запись по существующему слагу перезаписывает заметку.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| name | строка | да | — | имя-слаг заметки (стем файла) |
| content | строка | да | — | тело заметки в markdown; минимум 1 непустой символ |
| description | строка | нет | отсутствует | однострочное описание (крючок для индекса и префетча) |
| kind | строка | нет | `other` | классификация: `user`, `feedback`, `project`, `reference`, `other` |
| scope | строка | нет | `project` | область видимости |

Возвращает `name`, `scope`, `path`, `outcome` (`created` для новой заметки, `updated` при перезаписи) и `index_updated` (всегда `true`).

Ограничение слага: имя обязано быть одиночным стемом из символов `[A-Za-z0-9._-]`, не быть пустым, не быть `.` или `..`, не совпадать с именем `MEMORY` (зарезервированный индекс) и не содержать разделителей пути, `:` и символов, ломающих разбор индекса. Некорректный слаг отклоняется на этапе валидации.

`description` сворачивается в одну строку (любые пробельные символы заменяются одним пробелом); пустое или состоящее только из пробелов описание не записывается вовсе. Отдельного отображаемого заголовка нет — заголовком служит сам слаг.

### list

Перечисляет индекс (список строк-крючков) заданной области.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| scope | строка | нет | `project` | область видимости |

Возвращает `scope` и `entries` — список строк индекса, каждая с полями `title`, `file` и `hook`.

### delete

Удаляет заметку по слагу и убирает её строку из индекса.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| name | строка | да | — | имя-слаг удаляемой заметки |
| scope | строка | нет | `project` | область видимости |

Возвращает `name`, `scope`, `removed` (`false`, если заметки не было — операция без эффекта) и `index_updated` (изменился ли индекс).

### search

Ищет заметки в заданной области по релевантности BM25.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| query | строка | да | — | свободный текстовый запрос; минимум 1 непустой символ |
| scope | строка | нет | `project` | область видимости |
| max_results | целое или строка | нет | 100 | ограничение на число возвращаемых совпадений |

Возвращает `scope`, `query` и `hits` — совпадения по убыванию релевантности. Каждое совпадение несёт `name`, `title`, `kind`, `snippet` (фрагмент тела вокруг совпадения) и `score` (оценка BM25).

## Поведение и ограничения

- Каждая заметка — файл `<каталог_области>/<slug>.md` с frontmatter и телом markdown. Frontmatter хранит поля `name` (заголовок), необязательный `description` и `metadata.type` (классификация). Запись и перезапись идут атомарно (временный файл + переименование).
- Индекс области — файл `<каталог_области>/MEMORY.md` со строками вида `- [title](slug.md) — hook`. Крючок (`hook`) — это `description`, если он задан и непуст, иначе заголовок. Запись добавляет или заменяет строку индекса; удаление убирает её. Строки, не подходящие под формат индекса, при чтении индекса отбрасываются.
- Поиск BM25: насыщение частоты термина `k1 = 1.2`, нормализация длины документа `b = 0.75`, вес поля метаданных (заголовок + крючок) относительно тела — `2.0`. Термины токенизируются как максимальные последовательности буквенно-цифровых символов Юникода или `_`, всё остальное — разделитель. Кириллица и другие алфавиты обрабатываются; слитный текст CJK без разделителей образует один термин-последовательность (подстрока внутри него не совпадает).
- Ранжирование: совпадает любой термин запроса (семантика ИЛИ), повторы терминов запроса не умножают оценку. Совпадения с оценкой ниже 15% от оценки лучшего результата отбрасываются; лучший результат сохраняется всегда. При равных оценках сохраняется порядок индекса. Жёсткий потолок возвращаемых совпадений — 100.
- Записи читаются и перезаписываются сериализованно по каталогу области: блокировка защищает как файлы заметок, так и общий индекс, в том числе между разными сессиями и процессами, работающими с одной областью.
- Автоподгрузка: в момент старта сессии заметки подаются модели как системное сообщение, без вызова операций `list`/`read`. Область `user` подаётся с полными телами заметок и без ограничения объёма. Области `project` и `local` подаются только строками-крючками — тело такой заметки читается по требованию операцией `read`. Сбой загрузки одной области не прерывает старт сессии.
- Максимальный размер результата операции — 25 000 символов. Хранимые заметки при этом не изменяются.
- Правила наполнения: хранить только знания, которые стоит перенести в будущую сессию. Запрещено хранить секреты, журналы прогресса и статусов, преходящие факты и то, что дёшево восстанавливается из кода, git или текущего разговора. Для области `user` — только универсальные поведенческие правила, действующие в любой сессии и проекте, с классификацией `feedback`. Следует выбирать самую узкую подходящую область и сверять вспоминаемые факты с актуальными источниками.

## Примеры

Запись заметки проекта:

```json
{"operation": "write", "scope": "project", "name": "build-commands", "description": "Команды сборки и гейт проекта", "kind": "project", "content": "Сборка: cargo build. Гейт: cargo test && cargo clippy."}
```

Чтение заметки:

```json
{"operation": "read", "scope": "project", "name": "build-commands"}
```

Перечисление индекса области:

```json
{"operation": "list", "scope": "user"}
```

Поиск по запросу:

```json
{"operation": "search", "scope": "project", "query": "сборка гейт", "max_results": 5}
```

Удаление заметки:

```json
{"operation": "delete", "scope": "project", "name": "build-commands"}
```
