# cli-wrapper

Возможность, добавляемая через `Tools{add}`: превращает любой CLI-скрипт в типизированный инструмент агента. Конфигурация задаёт имя инструмента, интерпретатор и скрипт, а также набор именованных команд с типизированными параметрами; каждая команда становится операцией инструмента.

## Конфигурация

Возможность добавляется вызовом `Tools{operation:"add", capability:"cli-wrapper", config:{...}}`. Поля конфигурации:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| `name` | string | да | — | имя инструмента, которое вызывает модель; непустое |
| `description` | string | нет | пустое | описание инструмента, показывается в подсказке и схеме |
| `interpreter` | string | нет | пустое | программа-интерпретатор (например `"python"`, `"node"`); при пустом значении `script` запускается напрямую |
| `script` | string | да | — | путь к скрипту; непустой |
| `script_args` | array | нет | пустой | дополнительные аргументы между скриптом и именем команды |
| `timeout_ms` | integer | нет | `60000` | лимит времени одного вызова в миллисекундах; обязан лежать в `1..=60000` |
| `read_only` | boolean | нет | `false` | объявляет инструмент только-на-чтение и безопасным для параллельного запуска |
| `commands` | объект | да | — | именованные команды (минимум одна); ключи — имена операций |
| `setup` | объект | нет | отсутствует | автонастройка инструмента, оборачивающего резидентный процесс |

Каждая команда (`commands.<имя>`) описывается так:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| `description` | string | нет | отсутствует | описание команды |
| `params` | array | нет | пустой | упорядоченный список объявлений параметров |
| `required` | array | нет | пустой | имена обязательных параметров |
| `read_only` | boolean | нет | наследует `read_only` инструмента | переопределение только-на-чтение для этой команды |
| `resident_stop` | boolean | нет | `false` | помечает команду канонической остановкой резидента |

Объявление параметра (`params[]`):

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| `name` | string | да | — | имя параметра — оно же поле входа, которое заполняет модель |
| `type` | string | да | — | тип по JSON Schema: `string`, `integer`, `number`, `boolean`, `array` |
| `description` | string | нет | отсутствует | описание параметра |
| `style` | string | нет | `"positional"` | способ передачи: `positional` или `flag` |
| `flag` | string | нет | имя из `name` с заменой `_` на `-` | переопределение имени флага для `style: "flag"` |

Блок `setup` (резидент):

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| `probe` | array | да (непустой при активации) | — | хвост argv проверки готовности (выход 0 = готов) |
| `start` | array | нет | — | хвост argv запуска резидента; запускается отсоединённо |
| `ready_timeout_ms` | integer | нет | `10000` | сколько ждать готовности резидента после запуска, в миллисекундах |
| `ready_hint_ms` | integer | нет | отсутствует | ориентировочное время до готовности, показывается агенту |
| `log_file` | string | нет | `<каталог скрипта>/<имя>.serve.log` | куда пишутся stdout/stderr резидента; поддерживает `{session_id}` и `{cwd}` |
| `resident_key` | string | нет | отсутствует | логический идентификатор резидента; литеральный, без шаблонов |
| `scope` | string | нет | `"shared"` | область владения резидентом; поддерживается только `shared` |
| `skip` | boolean | нет | `false` | пропустить всю активацию резидента и сразу считать готовым |

## Как команды становятся операциями

Каждое имя в `commands` — допустимое значение поля `operation` инструмента. Вход вызова — плоский объект: `operation` плюс параметры команды. Параметры одной команды, использующие один и тот же `name`, собираются в единое свойство схемы; описание параметра, чей смысл привязан к конкретной операции, снабжается списком этих операций.

## Формирование командной строки

Вызов собирает argv в порядке:

```
[interpreter?] script script_args... operation [позиционные...] [флаги...]
```

- Позиционные параметры добавляются голым значением в порядке объявления.
- Флаговые параметры добавляются после, в порядке объявления, как `--<флаг> <значение>`; булево значение `true` даёт только `--<флаг>`, `false` опускает флаг; массив повторяет `--<флаг> <значение>` для каждого элемента.
- Позиционный массив раскрывается в несколько голых значений.
- Строковое значение передаётся как есть; числа и булевы значения — текстовым представлением (`42`, `3.14`, `true`/`false`).

## Код возврата и вывод

- stdout и stderr процесса читаются конкурентно и сливаются: stderr добавляется после stdout, когда непуст.
- `exit_code` — код завершения процесса; при отсутствии кода — `-1`.
- Ненулевой код завершения делает результат ошибочным (`is_error`).
- Превышение `timeout_ms` возвращает ошибку таймаута; пользовательское прерывание возвращает результат с `interrupted: true` и `exit_code: 130`.
- Для резидентного инструмента неудачный вызов, пока резидент стартует или упал, дополняется поясняющей заметкой; успешный вызов не делает вывод о готовности резидента — готовность подтверждается только каноническим `probe`.

## Резидентный процесс

- При активации инструмент сначала выполняет `probe`. Если проба уже проходит, `start` не запускается — живой резидент не убивается и не перезапускается; регистрируется факт присутствия, инструмент готов.
- Иначе выполняется атомарный захват резидента по разрешённому argv запуска (и по `resident_key`, когда задан): победитель запускает резидент отсоединённо (с отдельной группой процессов), записывает pid и порождает фоновый монитор готовности; проигравший ждёт чужой монитор. Активация возвращается сразу со статусом «прогрев», не блокируя добавление.
- Монитор опрашивает `probe` (пауза между пробами 500 мс, лимит пробы 5000 мс) до готовности либо до истечения `ready_timeout_ms`; при истечении резидент помечается неуспешным, а сессия уведомляется.
- Команда с `resident_stop: true` после кода 0 ждёт, пока `probe` перестанет проходить (проверка до 10 000 мс, окно пробы 2000 мс), и удаляет свою запись резидента. Итог фиксируется в `lifecycle`: `confirmed`, `unconfirmed`, `interrupted` или `unbound`; любой итог, кроме `confirmed`, помечает результат ошибочным, а запись сохраняется.

## Поведение и ограничения

- Обрезка вывода: параметр `_head` с целым N (минимум 1) оставляет первые N строк слитого вывода; при обрезке добавляется строка с количеством удержанных строк. На статус и аргументы команды не влияет.
- Максимальный размер результата инструмента — 30 000 символов.
- Имена параметров, начинающиеся с `_`, зарезервированы и в конфигурации запрещены.
- Шаблоны `{session_id}` и `{cwd}` подставляются только в `probe`, `start` и `log_file`; в `script_args` шаблонные переменные запрещены и вызывают ошибку конфигурации.
- Шаблон `{port}` и значение `scope: "per_agent"` не поддерживаются — задание любого из них даёт ошибку конфигурации.
- Флаг `read_only` — объявление: он помечает вызов читающим и безопасным для параллельного запуска. Фактическое поведение скрипта он не проверяет и прав процесса не ограничивает; по умолчанию инструмент считается изменяющим состояние.
- Конфигурация без `commands`, с пустым `name` или `script`, с `timeout_ms` вне `1..=60000`, с резидентной командой `resident_stop` без блока `setup` либо с более чем одной такой командой отклоняется ошибкой конфигурации.

## Примеры

Инструмент поверх системной команды: имя команды становится операцией, а параметры — её аргументами (`git status --short`):

```json
{
  "operation": "add",
  "capability": "cli-wrapper",
  "config": {
    "name": "Git",
    "description": "состояние и история репозитория",
    "script": "git",
    "read_only": true,
    "commands": {
      "status": {
        "description": "состояние рабочего дерева",
        "params": [{ "name": "short", "type": "boolean", "style": "flag", "flag": "short" }],
        "required": []
      },
      "log": {
        "description": "последние коммиты",
        "params": [
          { "name": "max_count", "type": "integer", "style": "flag", "flag": "max-count" },
          { "name": "path", "type": "string", "style": "positional" }
        ],
        "required": []
      }
    }
  }
}
```

Инструмент с интерпретатором и постоянными аргументами скрипта:

```json
{
  "operation": "add",
  "capability": "cli-wrapper",
  "config": {
    "name": "Index",
    "description": "поиск по индексу проекта",
    "interpreter": "python",
    "script": "tools/index.py",
    "script_args": ["--root", "."],
    "timeout_ms": 30000,
    "commands": {
      "lookup": {
        "description": "найти запись по идентификатору",
        "params": [{ "name": "id", "type": "string", "style": "positional" }],
        "required": ["id"],
        "read_only": true
      }
    }
  }
}
```

Инструмент поверх резидентного процесса:

```json
{
  "operation": "add",
  "capability": "cli-wrapper",
  "config": {
    "name": "Index",
    "interpreter": "python",
    "script": "tools/index.py",
    "commands": {
      "lookup": {
        "description": "найти запись по идентификатору",
        "params": [{ "name": "id", "type": "string", "style": "positional" }],
        "required": ["id"]
      },
      "stop": { "description": "остановить резидент", "params": [], "required": [], "resident_stop": true }
    },
    "setup": {
      "probe": ["status", "--brief"],
      "start": ["serve", "--port", "47777"],
      "ready_timeout_ms": 20000,
      "ready_hint_ms": 3000,
      "resident_key": "index-runtime"
    }
  }
}
```

Вызвать добавленный инструмент:

```json
{ "operation": "invoke", "name": "Index", "input": { "operation": "lookup", "id": "42" } }
```

Обрезать вывод длинной команды до первых строк:

```json
{ "operation": "invoke", "name": "Git", "input": { "operation": "log", "max_count": 100, "_head": 40 } }
```
