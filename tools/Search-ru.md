# Search

Поиск по проекту тремя способами: по именам файлов, по содержимому файлов регулярным выражением и по смыслу. Все режимы работают только на чтение.

## Режимы

Режим выбирается полем `mode` со значениями `files`, `content` или `smart`. Отсутствующее или неизвестное значение возвращает ошибку с указанием допустимых значений.

### files

Перечисляет файлы по шаблону имени.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| pattern | строка | да | — | шаблон имени, например `**/*.rs` или `*.{ts,tsx}` |
| path | строка | нет | рабочий каталог сессии | каталог для поиска; должен существовать и быть каталогом |

Поиск выполняется рекурсивно с учётом скрытых файлов и игнорируемых каталогов, отсортированный по времени изменения. Возвращается список путей, относительных к рабочему каталогу сессии (пути вне него возвращаются абсолютными), с числом файлов и признаком усечения. Результат ограничен 100 файлами; усечение отмечается в результате. Переменные окружения `KOT_GLOB_NO_IGNORE` и `KOT_GLOB_HIDDEN` (обе по умолчанию включены) управляют учётом игнорируемых и скрытых файлов, `KOT_GLOB_MAX_RESULTS` задаёт предел вместо 100.

### content

Ищет по содержимому файлов регулярным выражением.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| pattern | строка | да | — | регулярное выражение; ведущий `-` оборачивается в `-e` |
| path | строка | нет | рабочий каталог сессии | файл или каталог для поиска |
| glob | строка | нет | — | фильтр по имени; разделяется пробелами и запятыми, токены с `{` и `}` сохраняются целиком |
| output_mode | строка | нет | files_with_matches | `files_with_matches`, `content` или `count` |
| -B | целое число | нет | — | строки до совпадения |
| -A | целое число | нет | — | строки после совпадения |
| -C | целое число | нет | — | строки до и после |
| context | целое число | нет | — | строки до и после; приоритет context > -C > -B/-A |
| -n | булев | нет | true | показывать номера строк |
| -i | булев | нет | false | поиск без учёта регистра |
| type | строка | нет | — | фильтр по типу файла, например `rust`, `js`, `py` |
| head_limit | целое число | нет | 250 | максимум результатов; 0 означает без ограничения |
| offset | целое число | нет | 0 | пропустить первые N результатов перед head_limit |
| multiline | булев | нет | false | точка совпадает с переносом строки, шаблоны могут пересекать строки |

Из поиска исключаются каталоги систем контроля версий (`.git`, `.svn`, `.hg`, `.bzr`, `.jj`, `.sl`), учитываются скрытые файлы, а длинные строки обрезаются на 500 столбцах. Путь принимает как каталог, так и одиночный файл.

Режим `files_with_matches` возвращает только список файлов, отсортированный от новых к старым. Режим `content` возвращает совпавшие строки с номерами и пути относительно рабочего каталога. Режим `count` возвращает число совпадений по каждому файлу и сумму по всем файлам. Предел `head_limit` применяется после поиска; при фактическом усечении выставляется признак и в текст добавляется указание продолжить с новым `offset`.

### smart

Ищет по смыслу на естественном языке.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| query | строка | да | — | намерение поиска, например «где валидируется JWT» |
| max_results | целое число | нет | — | мягкий предел числа результатов |

Запрос выполняет ограниченный суб-агент, работающий только на чтение и имеющий доступ лишь к инструментам Files (чтение) и Search. Промежуточные вызовы суб-агента скрыты. Возвращается строгий список совпадений `hits`, где каждый элемент содержит путь, необязательный номер строки и обязательное пояснение, почему этот элемент релевантен. Суб-агент ограничен 8 ходами и обязан вернуть ответ в заданной структуре; невалидный ответ возвращается как ошибка. Если запуск суб-агента в текущей конфигурации недоступен, режим возвращает ошибку.

## Поведение и ограничения

Все режимы только для чтения, не разрушают состояние и безопасны при параллельном выполнении. Относительный путь `path` резолвится против рабочего каталога сессии, а не против рабочего каталога процесса. Абсолютный путь используется как есть. Для режима `files` путь с `~` раскрывается до домашнего каталога; в режиме `content` путь возвращается как есть.

Режимы `files` и `content` выполняются командой ripgrep, вызываемой по имени из PATH. Отсутствие ripgrep возвращает ошибку установки. Таймаут по умолчанию 20 секунд (переменная `KOT_GLOB_TIMEOUT_SECONDS`). Таймаут без результатов возвращает ошибку таймаута; таймаут с частичными результатами возвращает их как обычный результат: в режиме `files` они помечаются признаком усечения, а в режиме `content` при любом значении `output_mode` (`files_with_matches`, `content`, `count`) отдельного признака нет. Код завершения 1 означает отсутствие совпадений (не ошибка); код 2 означает ошибку регулярного выражения или неверные аргументы; прочие коды означают сбой. Ошибка EAGAIN повторяется один раз с одним потоком. Вывод ограничен 20 МБ (stderr — 1 МБ); при превышении хвостовая незавершённая строка отбрасывается.

UNC-путь в режиме `content` отклоняется сразу; в режиме `files` проверка откладывается без обращения к файловой системе. Несуществующий путь возвращает ошибку; в режиме `files` путь, не являющийся каталогом, также возвращает ошибку.

## Примеры

Перечисление всех исходников Rust:

```json
{"mode": "files", "pattern": "**/*.rs"}
```

Список файлов, содержащих вызов функции:

```json
{"mode": "content", "pattern": "fn validate_input", "glob": "*.rs", "output_mode": "files_with_matches"}
```

Совпавшие строки с контекстом в две строки до и после:

```json
{"mode": "content", "pattern": "MAX_READ_SIZE", "output_mode": "content", "context": 2, "-n": true}
```

Продолжение выдачи со следующей страницы:

```json
{"mode": "content", "pattern": "TODO", "output_mode": "content", "head_limit": 250, "offset": 250}
```

Смысловой поиск места реализации:

```json
{"mode": "smart", "query": "где проверяется валидность JWT-токена", "max_results": 5}
```
