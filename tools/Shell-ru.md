# Shell

Запускает команды в оболочке хост-системы и возвращает объединённый вывод. Один инструмент обслуживает все поддерживаемые оболочки (PowerShell, bash/sh, cmd), а выбор конкретного терминала выполняется внутри инструмента. Псевдонимы имени: `Bash`, `RunCommand`.

## Операции

Инструмент принимает необязательное поле `operation`; при отсутствии поля подразумевается операция `run`. Доступны операции: `run`, `set_default_shell`, `bash_output`, `kill`, `list_tasks`, `shell_open`, `shell_send`, `shell_read`, `shell_close`. Неизвестное значение `operation` — ошибка.

### run

Выполняет команду в выбранной оболочке и возвращает результат. Основная операция; именно она принимает вход вида `{ "command": "..." }` без поля `operation`.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| command | строка | да | — | Команда для выполнения, записанная в синтаксисе выбранной оболочки. |
| timeout | число или строка | нет | 60000 | Предел блокирующего ожидания в миллисекундах для переднего плана. Максимум 60000; большее значение — ошибка, а не ограничение. Игнорируется для фонового запуска. |
| description | строка | нет | — | Короткое описание из 5–10 слов; используется в интерфейсе и как подпись фоновой задачи. |
| run_in_background | булево или строка | нет | false | При `true` команда запускается отдельной фоновой задачей, вызов возвращается сразу с идентификатором задачи. |
| shell | строка | нет | — | Имя терминала для этого вызова (одно из доступных имён оболочек). При отсутствии используется сессионный, затем системный дефолт. |
| raw | булево или строка | нет | false | При `true` возвращает несжатый вывод; по умолчанию вывод проходит сжатие. |
| monitor | объект | нет | — | Настройка проактивного монитора для фонового запуска. Требует `run_in_background: true`. |

Возвращает: объединённый `stdout` (к нему дописывается `stderr`, если непустой), `exit_code`, `interrupted`, имя терминала `shell`, семейство `shell_kind`, семантическую трактовку кода возврата `return_code_interpretation`, `background_task_id` для фонового запуска, `monitor_id` при установленном мониторе, `persisted_output_path` при выгрузке вывода на диск, `is_image`, `no_output_expected`, `compression` (отчёт о сжатии).

Ограничения: `timeout` ограничен 60000 мс.

### set_default_shell

Переключает терминал по умолчанию для текущей сессии. Последующие `run` без явного `shell` используют новый дефолт.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| shell | строка | да | — | Имя терминала, который становится дефолтом сессии. Должно быть известным и доступным именем. |

Возвращает: новый дефолт `default_shell` и предыдущий переключённый дефолт `previous_default` (пусто, если сессия ранее не переключала дефолт).

Ограничения: неизвестное или недоступное имя — ошибка; подстановка не выполняется.

### bash_output

Читает новый (с последнего чтения) вывод фоновой задачи.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| task_id | строка | да | — | Идентификатор `bg_<n>`, возвращённый запускающим `run`. |
| block | булево или строка | нет | false | Режим ожидания: `false`/опущено — мгновенный снимок текущей дельты; `true` — ждать первого нового вывода или завершения; `"completion"` — ждать завершения и вернуть всю накопленную дельту одним вызовом. |
| timeout | число или строка | нет | 60000 | Предел ожидания для блокирующего чтения в миллисекундах. Максимум 60000. Игнорируется при мгновенном снимке. |
| filter | строка | нет | — | Регулярное выражение; возвращаемая дельта сводится к строкам, которые ему соответствуют. |
| raw | булево или строка | нет | false | При `true` возвращает несжатую дельту. |

Возвращает: `task_id`, `new_output` (дельта), `status` (`running`/`exited`/`killed`), `exit_code` после завершения, `compression`. В тексте блока после завершения добавляется строка вида `[task bg_<n> exited with code N]`.

Ограничения: несуществующий `task_id` — ошибка; неверное регулярное выражение `filter` — ошибка.

### kill

Останавливает фоновый элемент по типу идентификатора.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| task_id | строка | да | — | Идентификатор `bg_<n>` (завершить задачу), `mon_<n>` (снять монитор; задача продолжает работать) или `res_<n>` (остановить резидента). |

Возвращает: `task_id` и `success`. Для `bg_<n>` — `true`, если запущенная задача завершена, `false`, если она уже вышла. Для `mon_<n>`/`res_<n>` — `true`, если живой элемент остановлен/снят, `false`, если идентификатор уже отсутствует.

Ограничения: несуществующий `bg_<n>` — ошибка; отсутствующий `mon_<n>`/`res_<n>` — мягкий `success: false`.

### list_tasks

Перечисляет все фоновые задачи и мониторы, закреплённые на каждой, а также зарегистрированных резидентов.

Параметры: нет.

Возвращает: список задач (новейшие первыми) с полями `task_id`, `status`, `exit_code`, `description`, `output_bytes`, `persisted_output_path`, `monitors`, и список резидентов. Пустой список — это не ошибка; текст блока — `(no background tasks)`.

### shell_open

Открывает постоянную интерактивную сессию оболочки — один живой процесс-интерпретатор, чьё состояние (рабочий каталог, переменные окружения и оболочки) сохраняется между командами.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| shell | строка | нет | — | Имя терминала для сессии (те же имена, что и у `run`). При отсутствии — сессионный, затем системный дефолт. |
| cwd | строка | нет | каталог сессии | Рабочий каталог, в котором стартует сессия. |
| description | строка | нет | — | Короткое описание из 5–10 слов. |

Возвращает: `session_id` (`sh_<n>`) и `output` — вывод, захваченный в стартовом окне (приглашение/баннер).

Ограничения: несуществующий `cwd`, сбой запуска или превышение лимита сессий (по умолчанию 16 одновременных) — ошибка.

### shell_send

Отправляет команду или ввод в живую сессию и собирает выданный вывод. Состояние сессии сохраняется между отправками.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| session_id | строка | да | — | Идентификатор `sh_<n>` сессии. |
| input | строка | да | — | Команда или ввод для отправки; к нему дописывается `\r` (терминальный Enter) для выполнения. |
| timeout | число или строка | нет | 10000 | Предел окна сбора вывода в миллисекундах. Максимум 60000. |

Возвращает: `session_id`, `output` (дельта), `closed` (закрылась ли сессия). Окно также завершается раньше по тишине; команда сессии продолжает выполняться после закрытия окна.

Ограничения: отсутствующая или закрытая сессия — ошибка.

### shell_read

Инкрементально читает новый вывод живой сессии без отправки ввода — для догона длительной команды.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| session_id | строка | да | — | Идентификатор `sh_<n>` сессии. |
| timeout | число или строка | нет | 10000 | Предел окна сбора вывода в миллисекундах. Максимум 60000. |

Возвращает: `session_id`, `output` (дельта), `closed`.

### shell_close

Завершает процесс живой сессии и освобождает её слот.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| session_id | строка | да | — | Идентификатор `sh_<n>` сессии для закрытия. |

Возвращает: `session_id` и `success` (`true`, если запущенная сессия завершена).

Ограничения: отсутствующий идентификатор — ошибка; `success` равен `false`, когда сессия уже вышла.

## Поведение и ограничения

### Выбор оболочки

Инструмент выбирает терминал внутренним образом по имени. Имена по умолчанию: на Windows — `pwsh` (PowerShell) и `cmd` (cmd.exe); на POSIX — `bash` и `sh`.

Собственные именованные оболочки задаёт необязательный файл `<каталог_конфигурации>/shells.json` — JSON-массив записей:

| поле | тип | обязательно | смысл |
|---|---|---|---|
| name | строка | да | имя, которое указывается в параметре `shell`; уникально без учёта регистра; запись с именем системной оболочки её переопределяет |
| kind | строка | да | семейство синтаксиса: `bash`, `sh`, `pwsh` или `cmd` — определяет аргументы запуска, декодирование вывода и трактовку кода возврата |
| program | строка | нет | явный путь к интерпретатору; проверяется как путь на диске, поиск по `PATH` для него не выполняется. Без этого поля интерпретатор ищется в `PATH` по каноническим именам семейства. Указанный путь, отсутствующий на диске, — ошибка при выборе, без подстановки другой оболочки |
| edition | строка | нет | для семейства `pwsh`: `desktop` (PowerShell 5.1) или `core` (PowerShell 7+); без него редакция определяется по имени файла |
| default | булево | нет | сделать эту оболочку системным умолчанием (одну); сессионный дефолт из `set_default_shell` имеет приоритет |

```json
[
  { "name": "git-bash", "kind": "bash", "program": "C:/Program Files/Git/bin/bash.exe" },
  { "name": "ps5", "kind": "pwsh", "program": "C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe", "edition": "desktop" }
]
```

Файла нет — доступны только системные оболочки. Файл с ошибкой разбора не прерывает запуск: выводится предупреждение, и остаются системные оболочки.

Приоритет разрешения для `run` и `shell_open`: имя в вызове (`shell`) → сессионный дефолт (переключённый через `set_default_shell`) → системный дефолт. Системный дефолт: на Windows — `pwsh` (поиск `pwsh`, затем `powershell`, затем запасные пути Linux), на POSIX — `bash` с откатом на `sh`. `cmd` достижим только по явному имени и никогда не выбирается автоматически.

Выбор выполняется зондированием без запуска; результат мемоизируется на процесс. Отсутствующий интерпретатор или настроенный, но отсутствующий на диске путь — ошибка; молчаливой подстановки другой оболочки не происходит.

Параметры запуска команды: bash/sh — `-c <команда>`; PowerShell (обе редакции) — `-NoProfile -NonInteractive -Command <команда>`; cmd — `/C <команда>`.

### Таймауты и коды возврата

Жёсткий предел блокирующего ожидания, управляемого моделью, — 60000 мс (1 минута) для: переднепланового `run` (`timeout`), блокирующего `bash_output` (когда `block` резолвится в ожидание вывода или завершения), окна `shell_send`/`shell_read`. Значение ровно 60000 допустимо; большее — ошибка, никогда не ограничение. Предел не настраивается.

Таймаут по умолчанию для переднепланового `run` — 60000 мс. При истечении таймаута команда убивается целиком (всё дерево процессов) и инструмент возвращает ошибку таймаута.

Код возврата — код дочернего процесса. Если команда прервана пользователем (`interrupted: true`), код — 130 (соглашение 128+SIGINT). `stdout` и `stderr` объединяются: `stderr` дописывается к `stdout`, если непустой.

Трактовка кода возврата зависит от оболочки. bash: `grep`/`rg` с кодом 1 — «No matches found» (не ошибка), код 2 и выше — ошибка; `diff` с кодом 1 — «Files differ» (не ошибка), код 2 и выше — ошибка. PowerShell: `grep`/`rg`/`findstr` с кодом 1 — «No matches found»; `robocopy` — битовое поле (0 — «Already in sync», 1–7 — «Files copied», 8 и выше — ошибка). cmd: только правило по умолчанию — код 0 это успех. В остальных случаях успехом считается только код 0.

Декодирование вывода зависит от оболочки: PowerShell Desktop (5.1) выдаёт UTF-16 LE (с распознаванием BOM или по признаку NUL-байтов) и нормализует `\r\n` в `\n`; PowerShell Core (7+) и bash/sh/cmd — UTF-8 с потерями на недопустимых байтах.

### Фоновые задачи

При `run_in_background: true` команда отсоединяется в фоновую задачу, вызов возвращается сразу с идентификатором `bg_<n>` и текстом «Command running in background with ID bg_<n>». Идентификаторы монотонно возрастают от `bg_0`. stdout и stderr непрерывно сливаются в один буфер; статус задачи — `running`, `exited` (с кодом), `killed`.

Буфер накапливается в памяти до порога 64 МБ; после превышения вывод выгружается в файл `<runtime>/shell-bg/<id>.out`, а в памяти остаётся хвост размером 1 МБ. Путь файла доступен в `persisted_output_path`.

Вывод декодируется UTF-8 с потерями; незавершённая многобайтовая последовательность на границе чтения придерживается до следующего чтения, чтобы не разорвать символ между чтениями.

Список фоновых задач общий для процесса агента; при завершении сессии её задачи убиваются и удаляются вместе с файлами выгрузки. Осиротевшие файлы выгрузки от предыдущих запусков удаляются при старте.

Режим `block` для `bash_output`: `false`/опущено — мгновенный снимок; `true` — ждать первого нового вывода или завершения; строки `"completion"`, `"exit"`, `"until_exit"`, `"done"` — ждать завершения и вернуть всю дельту одним вызовом. Чтение `"completion"` возвращается только когда процесс остановился и оба потока полностью вычитаны.

### Мониторы

Монитор — проактивный наблюдатель, который запускается вместе с фоновым `run` при наличии поля `monitor`. Он наблюдает задачу с собственного курсора (начиная с байта 0, поэтому вывод между запуском и установкой не теряется) и при срабатывании доставляет уведомление в сессию без опроса. Возвращается идентификатор `mon_<n>`.

Поле `on` (что ждать): `completion` (по умолчанию) — завершение или убийство задачи; `output` — новая строка вывода соответствует `pattern`; `idle` — нет нового вывода `idle_secs` секунд; `heartbeat` — срабатывает каждые `interval_secs` секунд, пока задача работает.

Правила полей монитора:

| поле | обязательность | ограничение |
|---|---|---|
| on | нет (по умолчанию `completion`) | одно из `completion`/`output`/`idle`/`heartbeat` |
| pattern | требуется для `on:"output"` | непустое регулярное выражение; только с `output` |
| idle_secs | требуется для `on:"idle"` | целое ≥ 1; только с `idle` |
| interval_secs | требуется для `on:"heartbeat"` | целое ≥ 1; только с `heartbeat` |
| recurring | нет | см. ниже |
| throttle_secs | требуется для `on:"output"` + `recurring:true` | целое ≥ 1; только в этой комбинации |
| raw | нет | при `true` выдержка уведомления — сырой хвост без сжатия |

Повторение: `completion` — одноразовый (терминальный), `recurring: true` с ним недопустим. `output`/`idle` — одноразовые по умолчанию; `recurring: true` заставляет продолжать срабатывать (для `output` требуется `throttle_secs` — окно коалесценции, подавляющее шквал уведомлений; для `idle` — одно срабатывание на каждый эпизод тишины, новая активность перевзводит). `heartbeat` — повторяющийся по своей природе, `recurring: false` с ним недопустим.

Каждое числовое поле длительности монитора ограничено 100 годами (представимость таймера); большее значение — ошибка. Совпадение по `output` ведётся только по полным строкам; строка длиннее 64 КБ без завершения приводит к громкому закрытию монитора с сообщением об ошибке (никакого обрезания или префиксного совпадения). Выдержка уведомления — хвост до 8 КБ.

Несовместимая комбинация полей — ошибка до запуска задачи; задача не порождается. Если установка монитора неожиданно падает после запуска, задача убивается и возвращается ошибка. Монитор живёт дольше хода, его установившего; снимается явным `kill mon_<n>` (задача продолжает работать) или при завершении сессии.

### Интерактивные сессии

Сессия — один живой процесс-интерпретатор в псевдотерминале (ConPTY на Windows, pty на POSIX), размером 50 строк × 200 столбцов. Запуск: bash/sh — `-i`, PowerShell — `-NoLogo`, cmd — без флагов. По умолчанию допускается до 16 одновременных сессий.

Состояние (рабочий каталог, переменные окружения и оболочки, активированное виртуальное окружение) сохраняется между командами — именно для этого существуют сессии.

`shell_send` дописывает к вводу `\r` (терминальный Enter; `\n` не является Enter). Окно сбора завершается по тишине (нет новых байтов 250 мс) или по общему `timeout`; команда сессии продолжает выполняться после закрытия окна. Стартовое окно `shell_open` — 2 секунды.

Вывод сессии декодируется UTF-8 с потерями, из него удаляются ANSI-управляющие последовательности (CSI, OSC, одиночные управляющие байты); сохраняются печатный текст, `\n` и `\t`. Читатель сессии отвечает на терминальные запросы (DSR/DA), чтобы интерпретатор PowerShell не зависал.

`shell_close` завершает процесс, дожидается чтения оставшегося вывода (не более 1,5 с) и удаляет сессию из списка. При завершении сессии агента все её интерактивные сессии закрываются.

### Сжатие вывода

Вывод переднепланового `run` и дельт `bash_output`, а также выдержек уведомлений мониторов проходит сжатие. Поле `raw: true` отключает сжатие для вызова.

Сжатие подбирает именованный фильтр по строке команды; при отсутствии совпадения применяется универсальное безопасное преобразование: удаление ANSI-последовательностей → схлопывание пустых строк → дедупликация подряд идущих одинаковых строк → ограничение по строкам (сохраняются первые 160 и последние 200 строк, абсолютный предел 400 строк; опущенная середина помечается маркером).

Именованные фильтры по умолчанию: `cargo build/check`, `cargo clippy`, `cargo test`, `git status`, `git log`, `git diff/show`, `git push`, `rg/grep`. Каждый сохраняет сигнал (ошибки, предупреждения, проваленные тесты, итоги) и отбрасывает шум (строки прогресса сборки, подсказки, пустые разделители), применяет предел строк и при пустом результате выдаёт сообщение вида «ok …».

Переписанный вывод принимается только если он строго короче исходного и реально уменьшает количество токенов (BPE-подсчёт); иначе возвращается исходный текст. Отчёт о сжатии (`compression`) содержит исходный и сжатый размеры, оценку токенов, процент экономии, имя фильтра и (при записи tee-файла) путь.

При ненулевом коде возврата и фактическом сжатии полный несжатый вывод записывается в файл `<temp>/kot-shell-raw/shell-raw-*.log`, а в вывод добавляется подсказка с путём. Запись при неудаче молча деградирует (файла нет).

Результат инструмента ограничен 30000 символами.

### Прочее

- Команда исполняется с правами пользователя, запустившего агента.
- Если stdout целиком является data-URI изображения `image/*`, он декодируется, при превышении большей стороной 2000 пикселей уменьшается с сохранением пропорций (Lanczos3), перекодируется в PNG и отдаётся как блок изображения. Предел размера — 20 МБ; нечитаемое или всё ещё слишком большое изображение деградирует до текста.
- Поле `no_output_expected` равно `true`, когда команда по семантике не производит вывод (например, одиночный `cd`/`Set-Location`).
- Перед запуском процесс-группа настраивается так, чтобы при убийстве забиралось всё дерево потомков (cargo→rustc→линковщик), а не только прямая оболочка.

## Примеры

Запуск команды в оболочке по умолчанию:

```json
{ "command": "cargo test --workspace", "description": "Запуск тестов рабочей области" }
```

Запуск в фоне с монитором завершения:

```json
{
  "operation": "run",
  "command": "python train.py",
  "description": "Обучение модели",
  "run_in_background": true,
  "monitor": { "on": "completion" }
}
```

Запуск в фоне с монитором по строке вывода:

```json
{
  "operation": "run",
  "command": "cargo test --workspace",
  "run_in_background": true,
  "monitor": { "on": "output", "pattern": "FAILED", "recurring": true, "throttle_secs": 30 }
}
```

Чтение вывода фоновой задачи до завершения:

```json
{ "operation": "bash_output", "task_id": "bg_3", "block": "completion", "timeout": 30000 }
```

Открытие интерактивной сессии, отправка команды и чтение результата:

```json
{ "operation": "shell_open", "shell": "bash", "cwd": "/home/user/project" }
```

```json
{ "operation": "shell_send", "session_id": "sh_0", "input": "export KOTX=42 && echo $KOTX" }
```

Остановка фоновой задачи и снятие монитора:

```json
{ "operation": "kill", "task_id": "bg_3" }
```

```json
{ "operation": "kill", "task_id": "mon_1" }
```
