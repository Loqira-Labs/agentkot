# Plan

Инструмент ведения плана и задач агента: заменяет чеклист текущей сессии, хранит постоянный граф задач на диске с владельцами и зависимостями, а также переводит сессию в режим планирования только на чтение и обратно. Один инструмент с шестью операциями, различаемыми полем `operation`: `plan`, `task_add`, `task_update`, `task_list`, `enter_planning`, `finish_planning`.

## Операции

### plan

Заменяет чеклист сессии целиком одним вызовом. Чеклист живёт в памяти и принадлежит одной сессии; он не переживает перезапуск агента.

Параметр `todos` — массив элементов. Каждый элемент:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| content | строка | да | — | текст пункта чеклиста; минимум 1 непустой символ |
| status | строка | да | — | состояние пункта: `pending`, `in_progress` или `completed` |
| activeForm | строка | да | — | подпись-спиннер (настоящее продолженное время, например «Создаю тесты»); минимум 1 непустой символ |

Возвращает предыдущий чеклист (`old_todos`) и поданный список как есть (`new_todos`).

Поведение очистки: если все поданные пункты имеют статус `completed` (пустой список `[]` тоже удовлетворяет этому условию), сохранённый чеклист очищается, а в ответе по-прежнему возвращается исходный поданный список. Во всех остальных случаях сохранённый чеклист становится равен поданному списку.

### task_add

Создаёт одну задачу в постоянном графе задач.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| subject | строка | да | — | краткий заголовок задачи; минимум 1 непустой символ |
| description | строка | да | — | что нужно сделать |
| activeForm | строка | нет | отсутствует | подпись-спиннер |
| owner | строка | нет | отсутствует (владелец — сам агент) | имя агента-исполнителя, цель делегирования |
| metadata | объект | нет | пустой | произвольные прикреплённые метаданные |

Возвращает созданную задачу: её идентификатор (`id`, десятичная строка) и заголовок (`subject`). Новой задаче присваивается статус `pending`.

### task_update

Изменяет одну задачу: поля, статус, зависимости, владельца, метаданные.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| task_id | строка | да | — | идентификатор задачи; минимум 1 непустой символ |
| subject | строка | нет | без изменений | новый заголовок |
| description | строка | нет | без изменений | новое описание |
| activeForm | строка | нет | без изменений | новая подпись-спиннер |
| status | строка | нет | без изменений | `pending`, `in_progress`, `completed` или `deleted` |
| addBlocks | массив строк | нет | пустой | идентификаторы задач, которые эта задача блокирует |
| addBlockedBy | массив строк | нет | пустой | идентификаторы задач, которые блокируют эту задачу |
| owner | строка | нет | без изменений | новый владелец |
| metadata | объект | нет | без изменений | патч метаданных по ключам; значение `null` удаляет ключ |

Возвращает `success`, `task_id`, список реально изменённых полей (`updated_fields`), необязательный `error`, и необязательный `status_change` с переходом `from`/`to`.

Значение `status: "deleted"` — псевдостатус: задача удаляется, а её идентификатор каскадно удаляется из списков `blocks` и `blocked_by` всех остальных задач. Обновление несуществующей задачи — не ошибка: возвращается `success: false` со значением `error: "Task not found"`.

Метаданные объединяются по ключам: отсутствующие ключи добавляются, ключ со значением JSON `null` удаляется.

### task_list

Перечисляет задачи текущей доски.

Не принимает параметров, кроме `operation`.

Возвращает список видимых задач, отсортированных по числовому идентификатору. Задачи, у которых в метаданных есть истинный ключ `_internal`, скрываются. Из списка `blocked_by` каждой задачи исключаются завершённые (`completed`) блокирующие задачи — остаются только открытые блокировки. У каждой записи есть `id`, `subject`, `status`, необязательный `owner` и `blocked_by`.

### enter_planning

Переводит сессию в режим планирования — режим только на чтение, для исследования.

Не принимает параметров, кроме `operation`.

Возвращает сообщение-подтверждение. Операция идемпотентна: повторный вызов в режиме планирования допустим. Режим планирования — свойство главной сессии; суб-агент не может в него войти и получает ошибку.

### finish_planning

Завершает режим планирования: сохраняет текст плана, восстанавливает прежний режим сессии и завершает ход для проверки пользователем.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| plan | строка | нет | берётся уже существующий файл плана на диске | готовый текст плана в markdown |

Возвращает `plan` (текст из параметра либо прочитанный с диска), необязательный `file_path` (путь к файлу плана) и `restored_mode` (восстановленный режим, например `default`).

Текст плана записывается в файл `<plans_root>/<session-id>.md`. Если параметр `plan` не задан, в ответ подставляется содержимое уже существующего файла плана. Ошибка записи файла плана не прерывает операцию. После вызова ход завершается для проверки пользователем.

Вызов `finish_planning` вне режима планирования отклоняется на этапе валидации и в самом вызове.

## Поведение и ограничения

- Операции `task_list` и `enter_planning` — только на чтение. Операция `plan` не является безопасной для одновременного выполнения (неатомарное обновление чеклиста). Операции над задачами на диске сериализуются блокировкой.
- Чеклист операции `plan` хранится в памяти и принадлежит одной сессии; чеклисты разных сессий не смешиваются, и чеклист не переживает перезапуск. Постоянный граф задач хранится на диске.
- Постоянный граф задач хранится как один JSON-файл на задачу в каталоге `<tasks_root>/<list-id>/<id>.json`. Идентификатор доски (`list-id`) по умолчанию равен идентификатору сессии; у активного тиммейта, нанятого в команду, — это общая доска команды `team-<owner8>-<name>`. Переменная окружения `KOT_TASK_LIST_ID` переопределяет идентификатор доски.
- Идентификаторы задач — десятичные строки, выделяемые как «максимальный существующий + 1». Удаление задачи с наибольшим идентификатором не возвращает его к повторному использованию в пределах процесса.
- Мутации задач сериализуются эксклюзивной блокировкой на файле `<list-id>/.lock`: 30 попыток, откат 5–100 мс. Файлы задач пишутся атомарно (временный файл + переименование), чтение не требует блокировки.
- Связи зависимостей поддерживаются симметрично: запись «A блокирует B» добавляет B в `blocks` задачи A и A в `blocked_by` задачи B. Повторное добавление одной связи идемпотентно. Ссылка на несуществующую задачу не создаёт связи и не является ошибкой.
- При создании задачи срабатывает событие `TaskCreated`: блокирующее решение откатывает создание и возвращает ошибку. При переводе задачи в `completed` срабатывает `TaskCompleted`: блокирующее решение оставляет статус без изменений и возвращает `success: false` без ошибки.
- Повреждённый файл задачи (существующий, но не разбирающийся) даёт явную ошибку с именем файла; иностранные `.json`-файлы в каталоге доски, чей стем не является числом, пропускаются и не считаются задачами.
- Максимальный размер результата операции — 100 000 символов.

## Примеры

Замена чеклиста:

```json
{"operation": "plan", "todos": [
  {"content": "Изучить код", "status": "completed", "activeForm": "Изучаю код"},
  {"content": "Написать документацию", "status": "in_progress", "activeForm": "Пишу документацию"}
]}
```

Очистка чеклиста:

```json
{"operation": "plan", "todos": []}
```

Создание задачи с владельцем:

```json
{"operation": "task_add", "subject": "Добавить кэш", "description": "Реализовать кэш запросов", "owner": "worker-1"}
```

Создание блокировки: задача 2 ждёт завершения задачи 1:

```json
{"operation": "task_update", "task_id": "2", "addBlockedBy": ["1"]}
```

Перевод задачи в завершённое состояние:

```json
{"operation": "task_update", "task_id": "1", "status": "completed"}
```

Удаление задачи:

```json
{"operation": "task_update", "task_id": "3", "status": "deleted"}
```

Завершение планирования с передачей плана:

```json
{"operation": "finish_planning", "plan": "# План\n1. Сделать A\n2. Сделать B"}
```
