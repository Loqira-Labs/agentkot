# Agent

Создание и управление суб-агентами, тиммейтами и долгоживущими пайплайнами. Один инструмент, выбор действия задаётся полем `operation`; псевдоним `Task`.

## Операции

### spawn

Запускает суб-агента синхронно: родительская сессия ждёт завершения и получает итоговый отчёт в этом же ходе. Подходит для задач, результат которых нужен сразу для следующего шага.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"spawn"` |
| description | string | да | — | короткое (3–5 слов) описание задачи |
| prompt | string | да | — | задача для суб-агента |
| subagent_type | string | нет | general-purpose | тип агента (см. «Типы агентов») |
| model | string | нет | наследуется | переопределение модели: алиас `sonnet`/`opus`/`haiku` или канонический id |
| provider | string | нет | наследуется | переопределение провайдера (зарегистрированное имя) |
| effort | string | нет | наследуется | уровень рассуждений: `off`/`low`/`medium`/`high`/`xhigh`/`max` |
| isolation | string | нет | — | `"worktree"` или `"remote"`; `remote` недоступен |
| cwd | string | нет | наследуется | абсолютный путь рабочего каталога ребёнка |
| seed_history | string | нет | — | одноразовый `fork_id` из `History{fork}`; алиас `fork_from` |

Возвращает результат `completed`: `agent_id`, `agent_type`, `content` (текстовые блоки отчёта), `total_tool_use_count`, `total_duration_ms`, `total_tokens`, `usage` (четыре счётчика токенов), `prompt`, `worktree_path`/`worktree_branch` (если worktree сохранён), `transcript_path` (путь к полной транскрипции ребёнка). Если ребёнок не вернул текст, подставляется маркер отсутствия вывода и путь к транскрипции.

Ограничения: блокирует ход родителя до завершения ребёнка. Промежуточные вызовы инструментов ребёнка в транскрипцию родителя не попадают.

### delegate

Запускает суб-агента в фоне и сразу возвращает подтверждение запуска `async_launched`; терминальный результат приходит позже как `<task-notification>` в отдельном ходе. Пока идёт работа, с делегатом можно переписываться и останавливать его по адресу.

Параметры — те же, что у `spawn`, плюс:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| name | string | нет | UUID агента | явный адресуемый адрес; регистрируется после успешного запуска |
| until | object | нет | — | спецификация гейта-цели (см. «Гейт until») |

Возвращает `async_launched`: `agent_id`, `address` (явное имя или UUID), `description`, `prompt`, `output_file` (плановый путь отчёта `<sidechains>/<agent-uuid>.output.md`), `can_read_output_file`.

Ограничения: занятое имя — ошибка. Обычный делегат паркуется и имеет абсолютный лимит жизни 12 часов.

### hire

Создаёт постоянного пробуждаемого тиммейта: пир-сессию, которая отрабатывает брифинг, уходит в ожидание и пробуждается письмом (`send`). Живёт до `stop` или каскада закрытия ведущей сессии.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"hire"` |
| description | string | да | — | метка задачи тиммейта |
| prompt | string | да | — | брифинг — первый ход тиммейта |
| subagent_type | string | нет | general-purpose | тип агента |
| model | string | нет | наследуется | переопределение модели на всю жизнь тиммейта |
| provider | string | нет | наследуется | переопределение провайдера на всю жизнь тиммейта |
| effort | string | нет | наследуется | уровень рассуждений тиммейта |
| name | string | да | — | адресуемое имя (ключ почтового ящика) |
| team_name | string | нет | без команды | команда, в которую вступает тиммейт |
| mode | string | нет | — | только `"plan"` — вход в режим планирования |
| isolation | string | нет | — | `"worktree"` или `"remote"`; `remote` недоступен |
| seed_history | string | нет | — | одноразовый `fork_id`; алиас `fork_from` |

Возвращает `teammate_spawned`: `agent_id`, `session_id` (идентификатор сессии тиммейта), `name`, `team_name`.

Ограничения: брифинг выполняется в фоне; его сбой приходит ведущему письмом (никогда не теряется молча). Имя не может начинаться с `team:`, не может быть `orchestrator` и не может содержать `@`.

### send

Доставляет письмо на адрес агента. Письмо ставится в очередь re-entry целевой сессии и читается на её следующей границе хода. Операция peer-to-peer: отправить письмо может и запущенный суб-агент (отвечая ведущему).

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"send"` |
| to | string | да | — | адресат: владелец-агент, `team:<имя>`, `orchestrator`; через `@<домен>` — кросс-доменно |
| message | string | да | — | тело письма; свыше 30000 символов обрезается с маркером |

Возвращает `message_sent`: `to`, `delivered`, `reason` (при отказе), `roster` (известные адреса при отказе), `truncated`, `delivered_to` (список при широковещании), `unsynced_paths` (предупреждение о несинхронизированных путях отправителя).

Ограничения: неизвестный или неживой адресат — мягкий отказ `delivered:false` со списком адресов; ошибкой является только отсутствие маршрутизатора писем. Широковещание в команду исключает самого отправителя. Кросс-доменная доставка не раскрывает пути файлов отправителя.

### stop

Останавливает агента по адресу. Тиммейт распускается: текущая работа прерывается, сессия закрывается, имя снимается с регистрации, временный worktree удаляется, если в нём нет изменений, и сохраняется, если изменения есть. Делегат получает запрос на остановку и присылает уведомление `aborted`.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"stop"` |
| name | string | да | — | адрес агента для остановки |

Возвращает `stopped`: `name`, `stopped`, `kind` (`"teammate"`/`"delegate"`), `reason` (при отказе), `roster`.

Ограничения: неизвестный адрес — мягкий отказ со списком адресов. Квалифицированный чужой адрес (`name@domain`) — мягкий отказ по праву владения: жизненный цикл не пересекает домены.

### workflow

Запускает, осматривает или останавливает объявленный TOML-пайплайн. Запуск раскладывает пайплайн на долговременную доску (по задаче на шаг), готовые шаги выполняются конкурентно; терминальный результат приходит как `<task-notification>`.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"workflow"` |
| action | string | нет | `"run"` | `"run"`/`"status"`/`"stop"` |
| name | string | при run | — | стем файла объявления `<cwd>/.kot/workflows/<name>.toml` |
| definition | string | при run | — | инлайн-TOML-текст объявления |
| resume | string | при run | — | id существующего прогона `wf-<8hex>` |
| run_id | string | при status/stop | — | id прогона для осмотра/остановки |

При `run` обязателен ровно один из `name`/`definition`/`resume`. Возвращает `workflow_started` (`run_id`, `name`, `list_id`, `steps`, `resumed`), `workflow_status` (`run_id`, `name`, `state`, `steps`, `usage`, `reason`) или `workflow_stopped` (`run_id`, `stopped`, `reason`).

Формат объявления (TOML):

```toml
version = 1

[limits]
timeout = 43200000        # мс, по умолчанию и потолок 43200000 (12 ч)
max_iterations = 100      # по умолчанию и потолок 100

[[steps]]
name = "spec"             # обязательно, [A-Za-z0-9_-]+
prompt = "составь спецификацию по требованиям"
agent = "general-purpose" # по умолчанию general-purpose

[[steps]]
name = "build"
prompt = "реализуй по спецификации"
agent = "general-purpose"
model = "claude-opus-5"   # алиас или канонический id
provider = "anthropic"    # кросс-провайдерно для agent-шага/членов команды
depends_on = ["spec"]     # DAG-зависимости по именам шагов
inputs = ["spec"]         # подмножество depends_on
transactional = true      # worktree-транзакционность
[steps.until]
check = "npm test"
max_iterations = 50
timeout = 3600000
supervisor = { agent = "arbiter", model = "haiku" }
[steps.on_error]
retry = 2
action = "escalate"       # "stop" (по умолчанию) | "escalate"

[[steps]]
name = "review"
prompt = "ревью результата"
depends_on = ["build"]
[steps.team]
[[steps.team.members]]
role = "reviewer"         # обязательно, уникально в шаге
agent = "arbiter"
model = "haiku"

[[steps]]
name = "approve"
ask = "принять ли результат?"   # ask-гейт: вопрос владельцу
depends_on = ["review"]

[[steps]]
name = "deploy"
workflow = "deploy-pipeline"    # вложенный пайплайн по имени файла
depends_on = ["approve"]
```

Правила схемы: `version` обязателен и равен 1; неизвестные поля и неизвестная версия — ошибка. У шага ровно один исполнитель из `agent`/`team`/`workflow`/`ask`. Шаг с исполнителем `agent` или `team` обязан нести непустой `prompt`; шаг `workflow` или `ask` не должен нести `prompt` вовсе. `model` и `provider` допустимы только у шага `agent` — у команды их несёт каждый участник. Имя шага — `[A-Za-z0-9_-]+`, дубли запрещены. `depends_on` образует ациклический граф (неизвестные ссылки, самозависимость, циклы — ошибка); `inputs` — подмножество `depends_on`. У команды роли уникальны, пустая команда недопустима. `transactional` применим к шагам `agent` и `team` (по умолчанию true для шага с гейтом `until`, иначе false). Гейт `until` к шагу `ask` не применяется. Глубина вложенности пайплайнов — не более 3. Значения `until` проверяются по лимитам прогона (только вниз), супервизор должен быть известным типом агента. `on_error.retry` — дополнительные попытки (по умолчанию 0); `on_error.action` — `stop` (провал прогона, каскадная остановка) или `escalate` (пауза и письмо владельцу, возобновляемо).

Ограничения: объявление валидируется целиком до любых побочных эффектов. Состояние прогона (`running`/`paused`/`completed`/`failed`/`aborted`, либо `unknown` при мягком промахе) живёт на доске и в `run.json`; завершившийся прогон осматривается и после рестарта процесса. При `resume` завершённые шаги пропускаются, остальные перезапускаются со свежим бюджетом попыток. Остановка каскадная — отменяется всё поддерево узлов; приостановленный прогон финализируется напрямую.

### list_providers

Перечисляет провайдеров, доступных для кросс-провайдерного запуска суб-агента. Параметров нет.

Возвращает `providers_listed` со списком: `name`, `is_default` (провайдер текущей сессии), `spawnable` (можно ли указывать имя в `provider`), `model_count`. Собственный провайдер сессии идёт первым.

### list_models

Перечисляет модели провайдера (или всех провайдеров) с их возможностями.

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"list_models"` |
| provider | string | нет | все провайдеры | фильтр по зарегистрированному имени провайдера |

Возвращает `models_listed`: `provider`, `providers` (по провайдеру: `name`, `is_default`, `spawnable`, `models`), `reason`/`known_providers` (при мягком промахе по неизвестному фильтру). Карточка модели: `id`, `display_name`, `kind`, `for_chat`, `context_window`, `max_output_tokens`, `family`, `input_modalities`, `output_modalities`, `reasoning`, `tools`, `streaming`, `structured_outputs`, `preview`, `notes`.

Только модель с `for_chat: true` может вести агентскую сессию; карточка с `for_chat: false` — это медиа/эмбеддинг-строка, генерируемая через инструмент Media.

### current_model

Читает актуальное состояние модели вызывающей сессии. Параметров нет.

Возвращает `current_model`: `provider`, `model`, `effort`, `routing_version`, `capabilities` (контекстное окно, максимум выходных токенов, входные модальности, наличие рассуждений), `frozen_head_format_version`, `frozen_head_digest`, `fallback_lease`, `coordinator_generation`, `coordinator_next_seq`, `pending` (упорядоченные ожидающие изменения).

Ограничения: операция доступна, когда сессия публикует своё состояние; иначе возвращается ошибка.

### current_session

Читает актуальные рабочий каталог, постоянный контекст и режим вызывающей сессии. Параметров нет.

Возвращает `current_session`: `session_id`, `cwd`, `persistent_context`, `planning_mode`, `routing_version`, `frozen_head_digest`, `coordinator_generation`, `coordinator_next_seq`, `pending`.

Ограничения: как у `current_model`.

### status

Перечисляет агентов собственного домена вызывающей сессии: тиммейтов (по имени) и делегатов (в порядке регистрации) с жизненным циклом и живым состоянием. Параметров нет.

Возвращает `status` со строками: `name`, `address` (только у безымянного делегата, пока работает), `kind`, `team`, `agent_id`, `session_id`, `lifecycle`, `live_state` (`running`/`idle`/`closed`, либо отсутствует), `model`, `provider`, `pending_mail`, `last_wake_error`.

Ограничения: живое состояние берётся из зонда состояния; для неживой сессии поля зонда отсутствуют, модель/провайдер берутся из записи запуска. Состояние не выдумывается.

### set_model

Переключает провайдера/модель живого тиммейта собственного домена. Применяется со следующего хода; первый ход на новой паре перечитывает полную историю (инвалидируется prompt-кэш старой пары).

Параметры:

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| operation | string | да | — | `"set_model"` |
| name | string | да | — | почтовое имя тиммейта |
| model | string | да | — | целевой id модели из каталога целевого провайдера |
| provider | string | нет | текущий провайдер | целевой провайдер |

Возвращает `set_model`: `applied`, `name`, `session_id`, `old_provider`/`old_model`, `new_provider`/`new_model`, `event_id`, `publication_pending`, `metadata_pending`, `delivery_pending`, `reason`/`roster` (при отказе).

Ограничения: неизвестное имя — мягкий отказ со списком адресов. Имя делегата или квалифицированное чужое имя — отказ с пояснением. Промах по каталогу моделей — ошибка.

## Поведение и ограничения

### Типы агентов

Встроенные определения: `general-purpose`, `Explore`, `Planner`, `arbiter`. Неизвестный `subagent_type` — ошибка со списком доступных типов, без молчаливой замены.

- `general-purpose` — полный набор инструментов, автономное выполнение многошаговых задач; не одноразовый, не только-чтение.
- `Explore` — одноразовый исследователь только-чтение; набор инструментов `Files`, `Memory`, `Search`, `History`, `Shell`; возвращает один отчёт.
- `Planner` — одноразовый планировщик только-чтение; тот же набор инструментов; возвращает один отчёт.
- `arbiter` — роль судьи; набор инструментов `Files`, `Memory`, `Agent`, `Plan`; не одноразовый, не только-чтение; при запуске получает судейский брифинг.

Одноразовые типы: `Explore` и `Planner`. У `arbiter` при запуске в брифинг добавляется судейская инструкция; остальные задачи передаются без изменений.

### Изоляция

- `isolation:"worktree"` — временный git-worktree поверх git CLI из HEAD репозитория `cwd` сессии; каталог `<temp>/kot-agent-worktrees/agent-wt-<id8>`, ветка `agent/<id8>`; этот каталог становится рабочим каталогом ребёнка. По завершении очистка идемпотентна: без изменений — worktree удаляется, при изменениях — сохраняется и сообщается в выводе.
- `isolation:"remote"` — недоступен; вызов возвращает ошибку.
- `cwd` — абсолютное переопределение рабочего каталога ребёнка; взаимоисключающе с `worktree`.

Каждый ребёнок имеет изолированную сессию и изолированный виртуальный слой файлов. Правки ребёнка синхронизируются с диском до его завершения; собственные правки синхронизируются до запуска ребёнка, если он должен их видеть.

### Адресация почты

Адресат `to` — владелец-агент (явное имя или UUID безымянного делегата), `team:<имя>` (широковещание по активным членам, кроме отправителя), `orchestrator` (собственный ведущий), либо через `@<домен>` — кросс-доменно. Зарезервированы префикс `team:` и адрес `orchestrator`; имя не может содержать `@`.

### Наследование и переопределение провайдера/модели/уровня рассуждений

- `model`: без значения — наследуется модель родителя. Алиасы `sonnet`→`claude-sonnet-5`, `opus`→`claude-opus-5`, `haiku`→`claude-haiku-4-5-20251001` (без учёта регистра); любой другой непустой id передаётся как есть, без тихой подмены. Если провайдер ребёнка публикует каталог моделей, идентификатор вне каталога и модель, непригодная для чата, отклоняются до запуска ребёнка; провайдер без каталога получает идентификатор как есть.
- `provider`: без значения — наследуется провайдер родителя. При переопределении весь запуск ребёнка идёт на этом провайдере; незарегистрированное имя — ошибка. При заданном `provider` используется переданный `model` или дефолт этого провайдера; модель родителя через провайдеры не протекает.
- `effort`: явное значение выигрывает у наследования; кросс-провайдерные дети не наследуют уровень родителя; `off` отключает рассуждения там, где провайдер это поддерживает.

### seed_history (fork_from)

Одноразовый `fork_id` из `History{fork}` (алиас `fork_from`; передавать только одно). Изъятие проверяется по владельцу-сессии; пропуск — ошибка. Сессия, сама несущая маркер форк-гейта, не может повторно форкаться. У `hire` при сбое до реального старта тиммейта форк возвращается — его потребляет только реально стартовавший тиммейт.

### Гейт until (только delegate)

Объект `until` запускает цикл «рабочий → проверка»: после каждого хода рабочего команда `check` выполняется в его рабочем каталоге; код выхода 0 — готово; иначе вывод неудачи подаётся следующим ходом рабочего.

| поле | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| check | string | да | — | команда проверки; код 0 = готово |
| max_iterations | integer | нет | 100 | потолок итераций рабочего (минимум 1, жёсткий потолок 100) |
| timeout | integer | нет | 43200000 | общий бюджет цикла в миллисекундах (жёсткий потолок 43200000 = 12 ч) |
| supervisor | string или object | нет | — | имя типа агента или `{agent, model?, provider?}` |

Два подряд идентичных (нормализованных) вывода гейта — эскалация «нет прогресса». Супервизор при прошедшем гейте выносит вердикт первой строкой `VERDICT: accept|continue|escalate` (без учёта регистра): `accept` завершает, `continue` подаёт конкретику рабочим, `escalate` проваливает цикл. Отсутствие вердикта или неизвестный токен — громкий сбой, без тихого принятия. Значения выше потолков — ошибка, без тихой обрезки.

### Ограничения оркестрации у детей и тиммейтов

- Дети и тиммейты не оркестрируют: произвольные `spawn`/`delegate`/`hire`/`workflow` запрещены. Порождать суб-агентов может только оркестрирующая (главная) сессия.
- Сессия с ограниченным исследовательским грантом (объявленным в её первом сообщении) может синхронно порождать одноразовые только-чтение `Explore`/`Planner`; тиммейт дополнительно может использовать `Search{mode:"smart"}`.
- `send` доступен и запущенному ребёнку: он может ответить ведущему в любой момент работы.
- Тиммейты одной команды разделяют общую доску `Plan`.

### Лимиты и дефолты

- Максимальный размер результата инструмента — 100000 символов.
- Тело письма `send` — 30000 символов (обрезка с маркером).
- Сводка `<task-notification>` делегата и прогона workflow — 2000 символов.
- Лимит жизни обычного (припаркованного) делегата — 12 часов.
- Потолок итераций `until` — 100; бюджет `until` — 43200000 мс (12 ч).
- Версия схемы workflow — 1; глубина вложенности пайплайнов — 3.
- Предупреждение `send` называет не более 10 несинхронизированных путей отправителя.

### Обработка ошибок

- Промежуточные вызовы инструментов ребёнка скрыты от родителя: в ход родителя попадает только итоговый отчёт.
- Поле чужой операции (например, `name` в `spawn`) — ошибка, никогда не проглатывается молча.
- Мягкие отказы (`delivered:false`, `stopped:false`, `applied:false`, неизвестный `run_id`, неизвестный фильтр `provider`) возвращаются как обычный результат с `reason` и списком адресов/имён — модель исправляет адресата и повторяет.
- Прерывание: синхронный `spawn` связывает аборт родителя с ребёнком; `delegate` не связывает — ребёнок переживает прерывание родителя.

## Примеры

Синхронный исследователь по коду:

```json
{"operation": "spawn", "description": "найти валидацию токена", "prompt": "Найди, где в проекте проверяется JWT, и верни путь и номер строки", "subagent_type": "Explore"}
```

Фоновый делегат с именем и гейтом завершения:

```json
{"operation": "delegate", "description": "починить сборку", "prompt": "Исправь ошибки компиляции и добейся зелёной сборки", "name": "builder-1", "until": {"check": "npm run build", "max_iterations": 50}}
```

Найм тиммейта-ревьюера в команду:

```json
{"operation": "hire", "description": "ревьюер", "prompt": "Ревьюируй правки по правилам проекта и присылай вердикты почтой", "name": "reviewer", "team_name": "alpha"}
```

Письмо тиммейту и остановка:

```json
{"operation": "send", "to": "reviewer", "message": "проверь также обработку ошибок в новом модуле"}
```

```json
{"operation": "stop", "name": "reviewer"}
```

Переключение модели тиммейта и осмотр агентов:

```json
{"operation": "set_model", "name": "reviewer", "provider": "anthropic", "model": "claude-opus-5"}
```

```json
{"operation": "status"}
```
