# History

Инструмент чтения записанной истории переписки: извлекает прошлые результаты инструментов из стенограммы, перечисляет их, готовит срез истории для запуска ребёнка и перечисляет сессии. Возвращает байты, записанные в момент выполнения, а не изменённый текущий файл. Один инструмент с пятью операциями, различаемыми полем `operation`: `recover`, `query`, `fork`, `list_sessions`, `compact`.

Области видимости (`scope`): `session` (только текущая сессия), `project` (все сессии проекта) и `global` (все проекты на машине). По умолчанию: `project` для главного агента, `session` для суб-агента. `global` доступен только на чтение и только главному агенту; `fork` отклоняет `global`. Суб-агент с явной областью `project` или `global` получает ошибку.

## Операции

### recover

Возвращает один прошлый результат инструмента (обычно более раннее чтение файла) либо извлекает его по идентификатору вызова, и либо возвращает его как текст результата, либо повторно вставляет в стенограмму.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| file_path | строка | да, если нет tool_use_id | — | абсолютный путь, чей прошлый результат извлечь |
| tool_use_id | строка | да, если нет file_path | — | точный идентификатор вызова; извлекает любой прошлый результат, включая ошибки |
| mode | строка | нет | `return` | `return` — вернуть как текст результата; `inject` — дополнительно вставить в стенограмму |
| tool_name | строка | нет | `Files` | какой инструмент извлекать |
| tool_operation | строка | нет | `read`, если tool_name = `Files` | операция вызванного инструмента |
| strip_line_numbers | булево | нет | `true` для `Files` и `Read` | снять префиксы номеров строк вида `NN→` и `NN\t` |
| scope | строка | нет | `project` / `session` | горизонт истории |

`file_path` и `tool_use_id` взаимно исключают друг друга; ровно один из них обязателен. При извлечении по `tool_use_id` поля `tool_name` и `tool_operation` игнорируются.

Возвращает `file_path`, `recovered` (найден ли результат), `tool_use_id`, `captured_at` (время в стенограмме), `from_session` (сессия-источник при области `project`/`global`), `from_externalized` и `bytes` (длина текста после снятия нумерации). Не найдено — мягкий результат «нет», не ошибка. Чистое изображение (без текста) возвращается с ясным сообщением и нулевым числом байтов.

Режим `inject` добавляет короткое подтверждение и извлечённый текст как мета-сообщение в стенограмму, чтобы текст вошёл в контекст и пережил будущее сжатие. Режим `return` стенограмму не меняет.

### query

Перечисляет прошлые результаты инструментов по фильтрам, от новых к старым. Возвращает только метаданные без тел; тела отдаёт операция `recover`.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| tool_name | строка | нет | без фильтра | имя инструмента |
| tool_operation | строка | нет | без фильтра | операция инструмента; здесь нет подразумеваемого значения, перечисляются и записи, и правки |
| file_path | строка | нет | без фильтра | путь, который трогал вызов |
| limit | целое | нет | все совпадения | остановиться после N совпадений; минимум 1 |
| include_errors | булево | нет | `false` | включать ли ошибочные результаты |
| session_id | строка | нет | без фильтра | ограничить одной сессией (uuid); сессия должна быть достижима в области |
| scope | строка | нет | `project` / `session` | горизонт истории |

Фильтры объединяются логическим И. Возвращает `captures` — список записей, каждая с `tool_use_id`, `tool_name`, `tool_operation`, `file_path`, `is_error`, `captured_at`, `from_session`, `from_project` (только для `global`) и `bytes`.

### fork

Материализует срез истории в набор сообщений, пригодный для запуска ребёнка. Выдаёт одноразовый идентификатор `fork_id`, который передаётся инструменту `Agent` через `seed_history` при запуске ребёнка. Сама операция ребёнка не запускает.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| range | объект | нет | весь видимый контекст | какой срез истории форкать |
| strip_line_numbers | булево | нет | `true` для захвата `Files`/`Read` | снять нумерацию строк из тела захвата |
| scope | строка | нет | `project` / `session` | горизонт истории; `global` отклоняется |

Поле `range` — объект с ключом `kind` и значением одного из видов:

| kind | доп. поля | смысл |
|---|---|---|
| whole_context | — | весь текущий видимый контекст (по умолчанию) |
| last_n | `n` (целое, минимум 1) | последние N сообщений |
| before_compact_boundary | — | всё строго до границы сжатия контекста |
| capture | `tool_name`, `file_path`, необязательный `tool_operation` | один прошлый результат, свёрнутый в ведущее сообщение |
| whole_session | `session_id` (uuid) | целиком одна сессия |

Возвращает `fork_id`, `message_count` (число сообщений в срезе; `0` означает «нечего форкать»), `scope`, `range_kind` и `sessions_scanned` (число сессий, внёсших сообщения). Идентификатор одноразовый: повторное использование даёт ошибку «не найден или уже потреблён». Срез завершается синтетическим защитным сообщением.

### list_sessions

Перечисляет сессии области, от самой свежей активности к самой старой, для выбора одной для `query` или `fork`.

| параметр | тип | обязателен | по умолчанию | смысл |
|---|---|---|---|---|
| scope | строка | нет | `project` / `session` | горизонт истории |
| include_sidechains | булево | нет | `false` | включать ли стенограммы суб-агентов |
| limit | целое | нет | все сессии | оставить первые N сессий из списка |
| active_since | строка | нет | без фильтра | момент RFC3339; остаются сессии с активностью не раньше него |
| text | строка | нет | без фильтра | подстрока без учёта регистра по заголовку или первому запросу |

Фильтры объединяются логическим И (отсечка по времени → текст → ограничение). Некорректный `active_since` — ошибка. Возвращает `sessions` — список записей с `session_id`, `project_key` (только для `global`), `started_at`, `last_activity_at`, `message_count_estimate` (приблизительная оценка), `first_user_text`, `title`, `is_current` и `is_sidechain`.

### compact

Планирует сжатие контекста: перед следующим ответом сворачивает старший префикс текущей сессии в краткое резюме, оставляя самые последние сообщения. Параметров не принимает; всегда действует на живую сессию. Вызов всегда планирует сжатие и возвращает `scheduled: true`. Сам срез выполняется вне инструмента, до следующего обращения к модели. Применять только при действительно заполненном контексте (около 90%).

## Поведение и ограничения

- Операции `recover`, `query`, `fork` и `list_sessions` только читают историю. `compact` не является чтением (запрашивает переписывание контекста), но не разрушителен: полная стенограмма на диске не меняется.
- При отсутствии механизма чтения истории вызов операции, требующей чтения, возвращает ошибку «history reader unavailable»; запасного пути к живой файловой системе нет.
- Чтение истории сериализуется против флага отмены: при отмене сессии возвращается ошибка прерывания.
- Снятие номеров строк: снимается префикс `^\s*\d+[→\t]` в начале каждой строки, чтобы извлечённое тело было готово к записи. По умолчанию применяется к результатам инструментов `Files` и `Read`; для прочих инструментов по умолчанию не применяется; явное значение всегда побеждает.
- Разрешение пути при совпадении — лексическое: разделители приводятся к `/`, `.` и `..` разрешаются, буква диска Windows приводится к верхнему регистру, а имена сравниваются дословно без приведения регистра и без обращения к файловой системе.
- Результаты, помеченные как удалённые (tombstone), не всплывают ни в `query`, ни в `fork`, ни в диапазонах.
- Вынесенное за бюджет тело результата (spill) восстанавливается при чтении из каталога сессии; отсутствующий spill-файл — ошибка, а не усечённый предпросмотр.
- Инструмент никогда не выносит собственный результат за бюджет: восстановленное тело не может уйти в spill и зациклиться.
- Срез `fork` канонизируется и чинится до передачи: оборванные пары «вызов инструмента ↔ результат» восстанавливаются синтетическим ошибочным результатом, а висящие результаты отбрасываются. Срез перецепляется линейно, чтобы первый запрос ребёнка удовлетворял контракту провайдера.
- `compact` не проверяет заполненность контекста принудительно; рекомендация «около 90%» является указанием, а не гейтом.

## Примеры

Восстановить прошлое чтение файла:

```json
{"operation": "recover", "file_path": "C:/work/src/lib.rs"}
```

Восстановить результат вызова по идентификатору с вставкой в контекст:

```json
{"operation": "recover", "tool_use_id": "toolu_0123", "mode": "inject"}
```

Перечислить прошлые чтения файла:

```json
{"operation": "query", "tool_name": "Files", "tool_operation": "read", "file_path": "C:/work/src/lib.rs", "limit": 10}
```

Подготовить срез последних 5 сообщений для ребёнка:

```json
{"operation": "fork", "range": {"kind": "last_n", "n": 5}, "scope": "session"}
```

Перечислить сессии проекта с подстрокой в заголовке:

```json
{"operation": "list_sessions", "scope": "project", "text": "парсер", "limit": 20}
```

Сжать контекст текущей сессии:

```json
{"operation": "compact"}
```
