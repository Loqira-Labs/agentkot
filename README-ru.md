# KOT — просто лучший ИИ-харнесс

<h3 align="center">
  <a href="README.md">English</a> &nbsp;·&nbsp; <b>Русский</b> &nbsp;·&nbsp; <a href="README-zh.md">简体中文</a>
</h3>

**Один файл — это всё, что вам нужно.**

Лучший рабочий агент, которого можно поставить себе на машину. Один исполняемый файл: сам читает код и документы, ищет по проекту, правит файлы, запускает команды и длительные процессы, ведёт план и задачи, помнит важное между сессиями, нанимает других агентов и распределяет между ними работу — на разных провайдерах одновременно.

Он не спрашивает разрешения, не изображает заботу и не подстраивается под кривой процесс. Это инструмент. Работать с ним нужно как с инструментом.

## Позиция

**Безопасности нет и не будет.** Агент исполняет команды и правит файлы с правами пользователя, который его запустил. Ни песочницы, ни правил «разрешить/запретить/спросить», ни подтверждений на каждый шаг. Это осознанное решение: агент, который через шаг просит разрешения, не доводит задачу до результата, а тратит сессию на диалог о намерениях. Нужна изоляция — возьмите готовую: контейнер, виртуальная машина, отдельный пользователь, любая из сотен песочниц для агентов — и запустите `kot` внутри. Изоляция это свойство среды, а не агента.

**Скиллы не нужны.** Скилл — это текст с инструкцией, который кто-то оформил в отдельный механизм с реестром, установкой и версиями. У вас есть агент, который читает файлы и выполняет инструкции. Хотите работать по скиллу — дайте агенту документ и попросите работать по нему. Отдельная подсистема для чтения текста здесь не появится.

**MCP не нужен.** MCP — транспорт для инструментов, которых у агента нет. Здесь есть свои: оболочка, файлы, поиск, память, история, генерация медиа, оркестрация. Нужен внешний сервис разово — попросите агента дёрнуть его командой. Нужен постоянно — заверните его CLI в динамический инструмент через `Tools{add: "cli-wrapper"}`, и агент получит типизированные операции с проверкой параметров, без промежуточного протокола, лишнего процесса и его протокольных ограничений.

**Он не подстроится под ваш процесс.** Формулируйте задачу, давайте контекст, проверяйте результат. Если вам нужен агент, который вежливо соглашается с плохо поставленной задачей и подстраивается под неправильный пайплайн, — берите Claude Code, Codex и прочих.

## Главная сила: команда из разных провайдеров

Один агент на одной модели — это либо медленно, либо поверхностно, либо узкое горлышко. Здесь роли распределяются между провайдерами, и каждый участник работает на той модели, которая подходит его задаче.

Пример такого распределения — набор провайдеров и моделей выбираете вы сами, под свои задачи и доступные подписки:

| Роль                                   | Пример провайдера      | Зачем так                                           |
| -------------------------------------- | ---------------------- | --------------------------------------------------- |
| Ведущий агент                          | anthropic              | держит задачу целиком, пишет код, принимает решения |
| Архитектор, ревьюер                    | openai                 | независимый взгляд другой школы на план и на диффы  |
| Исследователи, разведка по коду        | deepseek               | десятки параллельных чтений на лёгкой модели        |
| Ревью безопасности, вторая пара глаз   | zai                    | ещё один независимый разбор на отдельной квоте      |
| Смысловой поиск внутри `Search{smart}` | любой лёгкий провайдер | поиск не должен занимать основную модель            |

Как это включается:

- каждый ключ в `providers.json` автоматически становится доступной целью запуска — отдельной настройки не нужно;
- `Agent{spawn|delegate|hire, provider, model, effort}` — ребёнок стартует на выбранном провайдере, модель родителя через провайдера не протекает;
- `Agent{set_model}` — переключение живого тиммейта на другого провайдера и модель между ходами;
- шаг пайплайна и участник командного шага несут собственные `provider` и `model`;
- `kot web --search-provider … --search-model …` — смысловой поиск уходит на отдельный, лёгкий провайдер.

Актуальные идентификаторы моделей каждого провайдера агент читает сам через `Agent{list_models}`, а в веб-интерфейсе они видны при выборе модели.

Результат: параллельная команда, где самая сильная модель занята тем, что действительно её требует, а рутину и разведку делают лёгкие.

## Бенчмарки

### Harness-Bench

[Harness-Bench](https://github.com/Qihoo360/harness-bench) меряет именно harness: 106 изолированных офлайн-задач агента в 8 рабочих категориях, модель зафиксирована, детерминированные oracle-валидаторы.

Одна и та же модель — DeepSeek V4 Flash; решает harness:

| Harness | Результат |
| ------- | --------- |
| **KOT** | **79.1%** |
| Hermes  | 76.2%     |

KOT на дешёвой быстрой модели обходит Hermes на той же модели — на 2.9 пункта по полному набору из 106 задач.

### Terminal-Bench 3.0

**Terminal-Bench 3.0** ([frontierbench.ai](https://www.frontierbench.ai/)) — настоящая терминальная работа: сборка, отладка, эксплуатация. Полный однопроходный прогон (k=1) по всему набору — 66 задач закреплённого датасета плюс 6 из предыдущей ревизии реестра, 72 trials, каждую задачу судит собственный верификатор. KOT работал на [DeepSeek V4 Flash](https://api-docs.deepseek.com/) с reasoning effort `high`. Полный ран: [72 trials на Harbor Hub](https://hub.harborframework.com/jobs/8f27a07f-4a88-41ce-b06c-6a713961c791).

```
mv kot.bin kot && chmod +x kot        # macOS

chmod +x kot                          # Linux
```

### Что обязано быть в системе

Две внешние программы, обе должны быть доступны в `PATH`:

Без них агент не запустится корректно: `kot doctor` пометит их как отсутствующие обязательные зависимости.

## Запуск

```
kot                       # то же, что kot web с настройками по умолчанию
kot web --addr 127.0.0.1:8080 --workspace C:\projects\my-app
kot web --new             # печатает адрес, открывающий сразу новую сессию
```

`kot web` поднимает HTTP-сервер на `127.0.0.1:8080` и печатает адрес. Рабочий каталог сессий задаёт `--workspace` (по умолчанию — текущий каталог). Разовые переопределения `--provider`, `--model`, `--search-provider`, `--search-model` действуют только на этот запуск и файл настроек не трогают.

Команды:

| Команда                                                           | Назначение                                                                                                  |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `kot web`                                                         | веб-интерфейс (команда по умолчанию)                                                                        |
| `kot login [--provider anthropic\|anthropic-oauth\|openai-codex]` | вход в подписку по OAuth; Claude-подписка использует провайдер `anthropic-oauth`                            |
| `kot logout [--provider <имя>]`                                   | удалить сохранённый токен подписки                                                                          |
| `kot config show`                                                 | показать действующую конфигурацию (секреты скрыты)                                                          |
| `kot config set provider <имя> [--base-url …]`                    | закрепить провайдера по умолчанию                                                                           |
| `kot config set model <id>`                                       | закрепить модель по умолчанию                                                                               |
| `kot config set key <провайдер>`                                  | сохранить API-ключ (скрытый ввод)                                                                           |
| `kot doctor [--live]`                                             | проверка окружения, конфигурации и учётных данных; `--live` делает минимальный реальный запрос к провайдеру |

Обычный вход печатает адрес авторизации и принимает код со страницы успеха в том же запуске. На машине без браузера вход выполняется в два вызова:

```
kot login --headless            # печатает адрес авторизации и завершает работу
kot login --code <КОД>          # завершает вход кодом со страницы успеха
```

Глобальный параметр `--config-dir` (переменная `KOT_CONFIG_DIR`) переносит весь каталог конфигурации.

При первом запуске без настроек агент проводит через выбор провайдера, ввод учётных данных и выбор модели, после чего записывает `settings.json`.

## Провайдеры и модели

Поддерживаются: `anthropic`, `anthropic-oauth`, `openai`, `openai-codex`, `gemini`, `deepseek`, `grok`, `openrouter`, `zai`, `moonshotai`, `together`, `fireworks`, `lmstudio`, `lmstudio-native`, `ollama`, `openai-generic`.

Учётные данные подключаются двумя путями:

- подписка по OAuth — `kot login --provider anthropic-oauth` для Claude Pro/Max и `kot login --provider openai-codex` для ChatGPT Plus/Pro; токены хранятся в `auth/`;
- API-ключ — `kot config set key <провайдер>`; `anthropic` — Anthropic-маршрут только по API-ключу, ключ пишется в `providers.json`.

`lmstudio`, `lmstudio-native` и `ollama` работают локально без ключа. `openai-generic` требует явный базовый URL и принимает необязательный ключ. Порядок разрешения ключа при работе: переменная окружения → `providers.json` → внешний помощник `api_key_helper`.

Каталог моделей встроен в бинарник: у каждой модели есть идентификатор, контекстное окно, предел вывода, модальности входа и выхода, поддержка рассуждений и инструментов, признак пригодности для чата. Вести сессию может только модель с признаком пригодности для чата; модели генерации изображений, видео и звука доступны инструменту Media. Полный каталог, включая медиа-модели, агент читает через `Agent{list_models}`; в веб-интерфейсе при выборе модели показываются чат-модели.

**Модель, которой нет во встроенном каталоге, добавляете вы** — в `<config-home>/models.json`: `kot models add --provider <имя> --id <id> --for-chat true …`, `kot models list`, `kot models remove`. Той же записью можно ПЕРЕОПРЕДЕЛИТЬ встроенную модель по отдельным полям — исправленное контекстное окно, другое отображаемое имя, уровни рассуждений, которые модель на самом деле принимает, — а `kot models add --clear <поле>` снимает одно переопределение, не удаляя остальные. В веб-интерфейсе то же самое делает форма модели: значок правки у любой модели селектора правит эту строку, последняя строка «+ Add model…» создаёт новую, а удаление убирает вашу запись (пользовательская модель уходит из списка, переопределённая встроенная возвращается к своему описанию). Пустое поле означает «как в программе», а серый текст за ним показывает, во что это разрешится. Запись, сделанную из командной строки, живой `kot web` подхватывает при следующем обновлении списка провайдеров — без перезапуска.

Уровень рассуждений задаётся при создании сессии и переключается на живой сессии: `off`, `low`, `medium`, `high`, `xhigh`, `max`.

## Веб-интерфейс

- Список проектов и сессий, создание, возобновление, откат к прошлому сообщению, закрытие и удаление сессии.
- Выбор рабочего каталога, провайдера, модели и уровня рассуждений — как при создании сессии, так и на живой сессии.
- Поток ответа в реальном времени, живая карточка исполняемого инструмента, очередь сообщений с правкой и удалением до отправки.
- Жёсткое прерывание хода и мягкое прерывание с отзывом.
- Панель фоновых задач: вывод, мониторы, остановка.
- Панель суб-агентов и тиммейтов: история работы ребёнка, письмо ему, остановка, восстановление тиммейтов после перезапуска.
- Список несинхронизированных файлов агента и их запись на диск одной кнопкой.
- Учёт расхода токенов и кэша по сессии.

## Оркестрация

Агент распределяет работу между другими агентами:

- **суб-агент синхронно** — запускается, отрабатывает задачу и возвращает отчёт в тот же ход;
- **делегат** — работает в фоне, о завершении сообщает уведомлением; с ним можно переписываться и остановить его; предельный срок жизни — 12 часов;
- **тиммейт** — постоянный участник, который просыпается от письма и живёт до явной остановки; тиммейты одной команды работают на общей доске задач;
- **гейт цели** — делегат повторяет ход, пока заданная команда проверки не вернёт нулевой код; проверяющий агент-супервизор может принять результат, вернуть на доработку или остановить цикл;
- **пайплайн** — объявленный в TOML граф шагов с зависимостями, командными шагами, вложенными пайплайнами и вопросами владельцу; прогон переживает перезапуск и возобновляется.

Ребёнок получает изолированную сессию и собственный виртуальный слой файлов; при необходимости — отдельный рабочий каталог или временный git-worktree. Провайдер, модель и уровень рассуждений ребёнка либо наследуются, либо задаются явно, в том числе на другого провайдера.

## Память, история и контекст

- **Память** — курируемые заметки в трёх областях: проект (общая через систему контроля версий), пользователь (общая для всех проектов машины), локальная (этот проект на этой машине). В начале каждой сессии заметки подаются агенту автоматически.
- **История** — полная стенограмма каждой сессии на диске. Агент извлекает из неё прошлые результаты, перечисляет их, переносит срез истории в новую сессию ребёнка.
- **Сжатие контекста** — старший префикс сворачивается в резюме, последние сообщения остаются дословными. Перед сворачиванием полная история записывается в архив рядом с сессией, а сама стенограмма остаётся неусечённой. Для суб-агентов автосжатие включено, для главной сессии — выключено и запускается по требованию.
- **Виртуальный слой файлов** — правки агента копятся отдельно от диска и попадают на диск синхронизацией. Слой восстанавливается из стенограммы после перезапуска.

## Данные на диске

Каталог конфигурации — `~/.kot` (переопределяется `KOT_CONFIG_DIR`).

```
~/.kot/
├── settings.json                  # настройки
├── providers.json                 # API-ключи
├── shells.json                    # именованные оболочки (необязательно)
├── auth/                          # токены подписок
├── memory/                        # заметки области «пользователь»
└── projects/<ключ-проекта>/
    ├── <сессия>.jsonl             # стенограмма сессии
    ├── <сессия>.media/            # вынесенные вложения
    ├── compact-archives/          # архивы истории перед сжатием
    └── sidechains/<агент>.jsonl   # стенограммы суб-агентов
```

Ключ проекта определяется по корню репозитория (или каталогу, если репозитория нет), поэтому сессии привязаны к проекту, а не к каталогу запуска. Каталог времени выполнения и каталог данных задаются переменными `KOT_RUNTIME_DIR` и `KOT_DATA_DIR`.

Заметки памяти проекта и локальной области лежат внутри самого проекта: `.kot/agent-memory` и `.kot/agent-memory-local`.

## Настройки

`settings.json` в каталоге конфигурации задаёт провайдера по умолчанию, модель, способ входа, переменные окружения для процессов, параметры сжатия контекста, параметры демона и клиента.

Полезные переменные окружения:

| Переменная                                                                                  | Действие                                               |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `KOT_CONFIG_DIR`, `KOT_RUNTIME_DIR`, `KOT_DATA_DIR`                                         | расположение конфигурации, времени выполнения и данных |
| `KOT_WEB_ADDR`, `KOT_WEB_WORKSPACE`, `KOT_WEB_PROVIDER`, `KOT_WEB_MODEL`, `KOT_WEB_NEW`     | значения параметров `kot web`                          |
| `KOT_GLOB_MAX_RESULTS`, `KOT_GLOB_TIMEOUT_SECONDS`, `KOT_GLOB_NO_IGNORE`, `KOT_GLOB_HIDDEN` | пределы и режим поиска по файлам                       |
| `KOT_TASK_LIST_ID`                                                                          | доска задач, с которой работает сессия                 |
| `ENABLE_TOOL_SEARCH`                                                                        | режим отложенных инструментов                          |
